# 实现方案（阶段 3 规格，待用户审阅）

状态：已批准，2026-10-13。

**用户已于 2026-10-13 批准，按文中的建议执行。** 用户同时给出了一句定位，作为今后取舍的总原则：
参照软件好用，是因为它只处理绘画的问题，不处理其他美术方面的问题，所以能兼顾绘画上的专业和好上手。
新软件照此办理：只做绘画。任何"顺便也能做"的功能，默认不做。

采用的决定：技术选型用方案二（Rust 加 Windows 原生接口、界面自绘）；像素格式 15 位定点；原生格式为 ZIP 加 JSON 加逐层 PNG；验收合格线取"不差于 GIMP 和画图"。新软件暂定名"纸笔"（`zhibi`）。

本文只依据行为规格（[feature-list.md](feature-list.md)、[interaction-analysis.md](interaction-analysis.md)）和公开文献来设计。
参照软件的内部实现没有被读取或转写；文中所有算法都是我们自己的设计，出处见 §4 的文献表。

设计取向来自用户的要求：**用着容易、结构简单，性能够用即可**。凡是"更快但更复杂"和"够用且简单"之间的选择，默认选后者。

## 1. 技术选型

下面的事实来自 2026-10-13 对各项目官方文档、发布页和源码仓库的查询（由一个后台助手完成，我没有逐条复核原文）。标"未核实"的是当时没能从一手来源确认的。动工前，选中方案涉及的条目要再核对一次。

### 1.1 查到的事实

| 维度 | 甲：C++ 加 Qt 6 | 乙：Rust 加 winit 加界面库 | 丙：SDL3 | 丁：直接用 Windows 原生接口 |
|------|-----------------|---------------------------|----------|------------------------------|
| Windows 上的笔输入后端 | Windows 指针输入为默认；Wintab 要通过私有接口开启，没有兼容性承诺 | 只有 Windows 指针输入；winit 不打算内置 Wintab | 只有 Windows 指针输入；Wintab 列在 3.6 的计划里 | 两种都能做，都要自己写 |
| 压力 / 倾斜 | 有 / 有 | 稳定版 0.30 只有压力；倾斜只在 0.31 测试版里 | 有 / 有 | 有 / 有 |

| 许可证 | 主要模块 LGPL-3.0 或 GPL-3.0，少数附加模块仅 GPL-3.0 | winit Apache-2.0；wgpu、egui、softbuffer 为 MIT 或 Apache-2.0；iced MIT；Slint 可选 GPL-3.0-only | zlib | 系统接口，适用 GPL 的系统库例外 |

| 跨平台 | 好 | 好 | 好 | 仅 Windows |

两点对选型影响最大：

1. **没有一个现成框架能直接满足"两种笔接口、全部历史样本、可切换"**。Qt 最接近，但 Wintab 靠私有接口，而用 Qt 的两个成熟绘画程序最后都自己写了数位板代码。也就是说，无论选哪个，笔输入这一层多半要自己写。
2. **笔输入这一层我们已经写过并测过**：研究阶段的 `pentap` 用系统原生接口取到了全部历史样本和 Wintab 设备信息，最简画线程序的跟随延迟约 3 毫秒。

### 1.2 三套候选方案

**方案一：C++ 加 Qt 6 Widgets**

- 好处：界面控件最全，高分屏和输入法现成，跨平台，先例最多。最快做出"功能齐全的界面"。
- 代价：依赖大，发布时要带一组运行库，与"结构简单"的方向相反；Wintab 仍要绕开框架自己接；C++ 的内存安全要靠自律。

**方案二：Rust 加 Windows 原生接口，界面自绘**

- 做法：窗口、菜单、对话框、文字输入框用系统原生控件（中文输入法因此直接可用）；画布和左侧面板自己画；笔输入直接向系统取；处理器渲染，按脏区域贴到窗口。分块存储、笔画引擎、文档、文件读写写成不依赖平台的独立模块。
- 好处：结构最简单，成品是一个不带运行库的可执行文件，这与参照软件给人的印象一致；笔输入完全可控，两种接口都能做；没有许可证问题；研究阶段的输入代码和测量工具可以直接沿用。
- 代价：只支持 Windows；面板里的控件要自己写（数量有限：滑块、色环、图层列表、大小表、工具盘、笔画预览）；高分屏适配要自己处理。
- 跨平台的余地：核心模块不依赖平台，将来换一个平台层即可，但界面层要重写。

**方案三：Rust 加 winit 加 softbuffer，再配一个界面库（Slint 或 egui）**

- 好处：跨平台；部件小而宽松；softbuffer 支持按脏区域提交。
- 代价：界面库都不传递完整的笔数据，所以仍要在框架旁边另接一条原生输入通道，等于同时承担方案二的输入工作和框架的学习与升级成本；egui 在 Windows 上的输入法问题对中文用户是实际障碍；这些库版本变动快。

SDL3 没有列为候选：它在 Windows 上取不到被合并的历史样本，目前没有 Wintab，也不带界面控件，三项都要自己补。

### 1.3 按评估维度比较

| 维度 | 方案一 | 方案二 | 方案三 |
|------|--------|--------|--------|
| 笔输入（两种接口、全部样本） | 指针输入好；Wintab 要自己接 | 都自己接，已有可用代码 | 都要在框架外自己接 |
| 低延迟渲染 | 够用 | 够用，已实测约 3 毫秒的下限 | 够用 |
| 许可证兼容 | 兼容 | 无依赖，最干净 | 兼容 |
| 跨平台前景 | 最好 | 只有核心可移植 | 好 |
| 生态与可维护性 | 成熟稳定 | 依赖最少，但界面代码全靠自己维护 | 库多但变动快 |
| 结构简单（用户的首要要求） | 最重 | 最轻 | 中等 |
| 做出第一个可用版本的工作量 | 界面省事，输入要补 | 界面费事，输入现成 | 两头都要做 |

### 1.4 建议

建议**方案二**。理由按分量排：

1. 用户的首要要求是结构简单，方案二的成品形态最接近这一点。
2. 最难、最影响手感的一层（笔输入和低延迟显示）在这个方案里风险最低，因为已经做过并量过。
3. 首批范围里需要自绘的控件只有六种，而首版又是固定布局，自绘界面的工作量是有界的。

它的主要代价是只支持 Windows。如果你希望将来能在其他系统上用，或者更看重尽快把界面铺开，方案一更合适。这是需要你决定的事。

## 2. 架构

自上而下六层，每层只依赖它下面的层。

```
界面层        面板、菜单、快捷键、对话框
视图层        画布视图：缩放/旋转/翻转的变换，脏区域的显示
文档层        文档、图层树、选区、撤销栈
笔画引擎      稳定器 → 插值 → 笔触绘制
分块存储      稀疏分块、写时复制
平台层        窗口、笔输入、文件、剪贴板
```

### 2.1 输入层（平台层的一部分）

- 把系统送来的笔事件统一成一种样本：时间戳、位置（浮点，窗口坐标）、压力（0 到 1）、阶段（悬停、落笔、移动、抬笔）。
- 一条系统消息里如果带着多个被合并的历史样本，全部取出，按时间顺序逐个交给上层，不丢弃。
- 事件一到就处理，不攒到下一帧。
- 启动时为画布窗口关闭系统的笔长按和轻拂手势（它们会推迟落笔的判定）。
- 修饰键的两条规则在这一层实现：按住临时切换工具；"修饰键 + 按键"之后 300 毫秒内忽略修饰键（F-151）。
- 首版只接 Windows 指针输入；Wintab 作为第二个后端在 P1 加入，两者产出同一种样本，上层不感知差别。

### 2.2 笔画引擎

一条笔画的处理顺序：

1. **坐标变换**：窗口坐标经视图变换的逆变换得到画布坐标。
2. **稳定器**：见 §3.1。
3. **插值**：把稀疏的样本连成平滑路径，见 §3.2。
4. **笔触绘制**：沿路径按固定间距落下圆形笔触，见 §3.3。
5. **报告脏区域**：返回这一段碰到的分块列表，交给视图层重画。

所有笔刷类工具（铅笔、喷枪、橡皮、选区笔，以及 P1 的混色笔刷）都是这一个引擎的参数预设（F-010）。

### 2.3 画布与分块存储

- 每个图层是一张稀疏的分块表：键是分块坐标，值是一个 64×64 像素的分块。没画过的地方不占内存。
- 像素格式：预乘透明度的 RGBA，每通道 16 位整数中取 15 位定点（数值 0 到 32768）。好处是低浓度反复叠涂时不会像 8 位那样出现色带，代价是内存翻倍。分块边长和这种定点格式都取自开源项目 MyPaint 的公开做法（前者已核实，后者未核实，见 §4）。
- 分块是写时复制的：撤销栈和恢复文件只需要保留对旧分块的引用，不必整层拷贝。
- 画布边长上限首版定为 16384 像素（F-172）。

### 2.4 渲染管线

- 全部在处理器上完成，不依赖图形处理器。依据有两条：研究阶段没有在参照软件里发现任何图形处理器接口的痕迹（这是推断，不是确证），而它实测比两款对照软件都跟手；我们自己"收到事件立刻用系统绘图接口画"的最简程序，跟随延迟约 3 毫秒。所以这条路对"够用"有很大余量。
- 每个分块缓存一份"所有可见图层合成后"的 8 位显示结果。笔画只让它碰到的分块失效。
- 视图层把失效分块覆盖的屏幕区域按当前的缩放、旋转、翻转重新采样，只把这块区域提交给窗口。
- 缩小显示时使用逐级减半的缓存，避免每次都从原始分辨率采样。
- 正在画的那一笔先画在一张临时的笔画层上，显示时叠在当前图层上方；抬笔时并入图层。这样"同一笔内不重复加深"和"撤销一整笔"都很直接。

### 2.5 图层合成

- 图层树自下而上合成，支持不透明度、可见性、混合模式；P1 加剪贴组、文件夹、锁定。
- 混合模式的公式采用 W3C《Compositing and Blending Level 1》这份公开标准，首版 8 种：正常、正片叠底、滤色、叠加、变暗、变亮、线性减淡、差值。

### 2.6 撤销系统

- 撤销栈里的每一项是一条命令。绘制类命令保存"被改动的分块在改动前的版本"；结构类命令（新建、删除、排序图层等）保存逆操作所需的信息。
- 文档记住上次保存时栈顶的位置；栈顶回到这个位置时，未保存标记消失（F-002）。
- 首版全部放在内存里，按占用设上限，至少保留 100 步。P1 把较旧的分块写到临时文件（F-182）。

### 2.7 界面层

- 固定布局：左侧两列面板，其余全部是画布；首版不做面板拖放。
- 需要自己画的控件：色环、带数值的滑块、图层列表、笔刷大小表、笔画预览。
- 首版的菜单项总数控制在 60 以内，会打开模态对话框的命令不超过 6 个。
- 所有设置（键位、工具预设、大小表、窗口状态）存成用户目录下的文本文件，删掉即恢复出厂（F-163）。

## 3. 关键算法：我们自己的设计

### 3.1 稳定器

行为目标见 F-016 至 F-018。设计：

- 档位 N（0 到 15）对应一个长度为 N+1 的滑动窗口，对窗口内样本的位置和压力分别取等权平均，平均值作为输出点。
- 落笔时：位置窗口全部填成落笔点（线从落笔处开始，不会从别处飞过来）；压力窗口全部填零（所以线头自然渐细，F-018）。
- 开发中的修正（M0）：压力窗口取 N+3 个样本，比位置窗口多 2 个（档位 0 不平滑）。原因是两个窗口等长时，仿真得到的渐细长度只有规格实测值的一半左右；多 2 个样本后，档位 1 / 2 / 3 / 5 / 8 / 15 的仿真值为 11 / 13 / 15 / 19 / 24 / 38 像素，规格里的参照值为 11 / 13 / 14 / 18 / 24 / 39。
- 抬笔时：把窗口里还没有体现到输出上的原始样本依次补画出来，一直画到抬笔位置（F-017）。做法是每一步从窗口尾部去掉一个最旧的样本再取平均，直到窗口只剩最后一个样本。
- 滑动平均是教科书上的标准滤波器。选它而不是自适应滤波器，是因为行为规格要求"同一档位永远是同一种手感"，而且实测的保留比例与它吻合。
- 已知缺口：参照软件实测的延迟增长比这个模型的理论值小。首版先按本设计实现，用 `strokebench` 测出我们自己的延迟曲线后再决定是否调整权重（例如让较新的样本权重更大）。
- 更强的档位（F-019，P2）另行设计，候选是公开的"拉绳"模型：笔刷被一根固定长度的绳子拖着走，笔在绳长范围内移动时笔刷不动。

### 3.2 样本间插值

- 相邻的稳定器输出点之间用向心 Catmull-Rom 样条连接。向心参数化不会在尖角和密集样本处产生自交或尖刺，这是公开文献里的结论（见 §4）。
- 沿曲线按弧长等距取点，间距取当前笔触直径的一个固定比例；压力在样本间线性插值。
- 最后一段（最新的两个点之间）先按直线画，等下一个点到来后再用曲线替换。这样墨迹不必等下一个样本就能跟到笔尖。

### 3.3 笔触绘制

- 笔触是一个圆：到圆心的距离小于半径处完全覆盖，边缘在约一个像素宽的范围内线性过渡到零。"边缘硬度"参数把这个过渡带加宽。
- 半径 = 最小半径 +（最大半径 − 最小半径）× 压力（F-011、F-013）。半径可以小于一个像素，此时靠覆盖率表现，所以细线是渐渐变淡而不是突然断掉。
- 同一笔之内，每个像素的覆盖率取各笔触的最大值，而不是累加；抬笔时再按浓度并入图层。这样一笔之内来回涂不会越涂越深。
- 橡皮是同一个过程，只是并入时做的是减少不透明度。

### 3.4 混色笔刷（P1）

- 行为规格里这一项没有实测数据（F-023），所以不以参照软件为目标，只要求"在两块颜色之间来回涂能得到平滑过渡"。
- 设计：笔刷带着一个"当前载色"。每落一个笔触，先读取笔触下方画布的平均颜色，按"混色"参数把载色向它靠拢，再按"持续"参数决定载色保留多少，最后用载色绘制。"稀释"参数降低绘制时的不透明度。
- 颜色混合首版在线性光 RGB 里做。基于颜料光谱的混合（Kubelka-Munk 一类）效果更像真颜料，但复杂得多，留作以后的可选项。

### 3.5 带缝隙闭合的填充（P1）

- 目标见 F-071：线稿有小缺口时不漏色。
- 设计：先对"线"的区域做距离变换，得到每个空白像素到最近线条的距离；泛洪填充时，不允许从"距离大于容差的区域"穿过"距离小于容差的瓶颈"进入另一片区域。实现细节在动工前参照公开的开源实现再定。
- M2 实际做成的样子（`core/src/fill.rs`）：
  1. 先做普通的泛洪，得到与起点相连、颜色在容差内的区域。
  2. 算出区域里每个像素离最近的边界有多远（倒角距离）。比"缝隙宽度的一半"更宽敞的地方，是一个比缝隙大的圆放得进去的地方；只保留其中包含起点的那一片。
  3. 剩下那些窄的地方（墙角、尖端、窄缝）按"分水岭"的办法分给相邻的宽敞区域：从宽到窄同时向外漫，在瓶颈最窄的地方相遇，缺口就在那里被封住。只挨着一片区域的窄地方整个归它，所以墙角和尖端不会留下没填到的边。
  4. 软边：从区域边界向线条里探，颜色还在持续远离起点色的那几个像素按比例算进来，探到颜色不再变的地方（线芯）为止。这样填色一直铺到线芯跟前，线的抗锯齿边底下不留浅色的缝，线芯也不会被吃掉。
  - 起点本身就落在比缝隙还窄的地方时，圆的大小减到当地宽度的一半，细长的区域照样能作为细长的区域填上。
  - 这套做法是照公开文献里的想法自己搭的（"困球"分割、带标记的分水岭、倒角距离），出处写在源文件开头，凭记忆写的，细节没有逐条核对。

### 3.6 马克笔（F-031）

- 目标：叠涂不越叠越深，颜色平滑地向新色过渡。用户 2026-10-14 拿参照软件的马克笔和我们的第一版对比，参照软件两笔交叉处没有变深。
- 公开资料对参照软件马克笔的描述（只有行为，没有算法）：Krita 手册说它的"Marker"模式"只有这一笔比图层上已有的更不透明时才提高不透明度，并混合颜色，就像参照软件的马克笔"；Drawpile 的开发日志说它的"Marker"模式"只提高不透明度，但总是混合颜色，和参照软件的马克笔一样"。
- 我们的做法：笔刷引擎已经保证一笔之内同一个像素只按覆盖率最大的那一次计（§3.3）。落笔时，设这一笔在某像素上的强度为 a（覆盖率乘浓度），原有像素的不透明度为 Da：
  - 不透明度 = max(Da, a)。比原有的淡的笔落上去，不透明度不变；永远不会越叠越浓。
  - 颜色 = 普通覆盖（source-over）时会得到的那个颜色，即预乘的"a·笔色 + (1−a)·原色"除以"a + (1−a)·Da"。空白处就是笔色；同色叠涂颜色不变；换色时按 a 的大小向新色过渡。
  - 两项都是我们按上面的行为描述自己定的，没有参照任何一家的实现。
- 保护不透明度时：颜色照上面算，不透明度保持原样。
- 出厂参数：大小 30、粗细不随压力变（最小大小 100%）、浓度 100%、最小浓度 30%（压力只管浓淡）、边缘硬度 100%（硬边，上色时边缘干净；用户反映 90% 时大笔刷边缘太糊，见下一条）。
- 边缘软硬对所有笔刷都可调（"边缘硬度"滑块）。软边的宽度与"1 − 硬度"的平方乘半径成正比：硬度 90% 时只有半径的 1%，500 像素的笔边缘只糊三四个像素；硬度 0 时从圆心一直软到边上。原先是一次方，大笔刷上硬度 90% 就糊出二十多个像素，滑块能用的范围全挤在最右边。
- 第一版（同一天）用的是"叠色"：颜色与已有颜色相乘，叠涂变深。用户对比之后改成了现在的做法。
- 不带拖色（画的时候把底下的颜色带着走）。有的用户把参照软件的马克笔说成带"持续"的混色笔，这类效果归 F-023 混色笔刷。

## 5. 文件格式

### 5.1 原生格式

要求：自己的、公开的、结构简单、别人写个脚本就能读。

- 一个 ZIP 容器，里面是：
  - `document.json`：画布尺寸、分辨率、背景、图层树（每层的名称、类型、可见性、不透明度、混合模式、锁定、偏移、对应的像素文件名）。
  - `layers/` 目录：每个图层一个 16 位 PNG，只包含该层有内容的外接矩形。
  - `merged.png`：合成后的整图，供其他程序和文件管理器预览。
  - `thumbnail.png`：缩略图。
- 版本号写在 `document.json` 里。读到不认识的字段时忽略；读到比自己新的版本号时拒绝打开并说明原因。（原先写的是"保留并原样写回"，开发时改掉了：要让未知字段跟着图层一起被排序、复制、删除，文档结构会为一个还不存在的需求变复杂。）
- 这个结构有意贴近 OpenRaster（同样是 ZIP 加一张清单加逐层 PNG），所以导出 ORA 几乎只是换一张清单。

### 5.2 交换格式

| 格式 | 读 | 写 | 说明 | 优先级 |
|------|----|----|------|--------|
| PNG | 是 | 是 | 合成图；透明背景时带透明通道 | MVP |
| OpenRaster | 是 | 是 | 图层、不透明度、可见性、常用混合模式。M2 已做 | P1 |
| PSD | 是 | 是 | 只处理 8 位 RGB、普通像素图层、不透明度、可见性、常用混合模式；遇到不支持的内容时提示并跳过，不让文件打不开。M2 已做，另外能读每通道 16 位的文件 | P1 |
| JPEG | 是 | 是 | 合成图。还没做 | P1 |

两种分层格式都是每通道 8 位，导出时像素从 15 位降到 8 位；画布的背景色写成最底下一个名叫"背景"的不透明图层，读回时再认出来。各自丢什么、读入时忽略什么，见 §6 的"M2 实测结果"。

参照软件的私有格式不读不写。

关于参照值的一条更正：测量时画面里的笔刷光标圆环有一部分压在墨迹上，这会让面积法少算一小段墨迹。少算的长度是固定的几个像素，所以笔速越慢、折合成的时间越长。规格里参照软件在 200 像素/秒下的跟随延迟（关稳定器 12.8 毫秒、默认档 23.3 毫秒）因此偏大，偏大多少没有量过；1000 像素/秒及以上受影响不超过约 3 毫秒。我们自己在 200 像素/秒下读到的 16.4 毫秒同样含有这个偏差。验收只用 1000 像素/秒的数值，结论不受影响。

仍然存在的问题：

- 稳定器高档位的跟随延迟比参照软件大：档位 3 / 8 / 15 为 12.1 / 24.1 / 41.1 毫秒，参照为 15.9 / 21.2 / 29.5。平滑效果一致，滞后更多。原因见 §3.1 的模型缺口，还没有解决办法。
- 档位 15 的"抬笔后画完用时"是 9.8 毫秒，贴着 10 毫秒的线。
- 导出和保存对话框默认打开系统的"文档"文件夹；没有记住上次用的位置。
- 保存时要先把整张画布合成一遍来生成预览图，最大尺寸（16384×16384）下这一步约需 800 MB 内存。4000×3000、三层的画布实测保存 0.7 秒、打开 0.3 秒。
- 没有用真实的笔做过系统测试。M0 完成后用户试画过，反馈是"还行"。

开发中发现并修掉的问题：

- **图层混合的舍入误差**：非"正常"模式下向下合并时，几项各自四舍五入后相加，颜色可能比透明度多出 1，成为不合法的预乘像素，存盘再读回会差 1。这是写文件格式的助手在核对"逐像素一致"时发现的。已在混合函数里压回去，并加了覆盖 8 种模式的测试。
- **读入文件后新建图层可能重名**：编号现在会跳过已被用掉的名字。
- **一笔被拆成一个点加一条线**：笔在感应范围内时，系统会不时补发不带"来自笔"标记的鼠标移动消息，原先被当成鼠标处理，把正在画的一笔打断了。M0 里就有这个毛病，只是自动测试的笔画中间没有停顿，没暴露出来。现在笔在感应范围内时一律不理会这类鼠标消息。
- **测量工具的面积法又修了一次**：改成"总面积 ÷ 总长度"之后，起笔渐细较长的笔画（稳定器高档位）延迟被高估约 10 毫秒。现在用线的中段各列墨量的平均值，对旋转和渐细两种情况都不偏。上表里的数字是修正后重测的。

M2 做了什么：

- **选区**：矩形选框、套索、魔棒三个工具，按住 Shift 加选、Alt 减选；"选择"菜单里有全选、取消、反选、扩大和收缩 1 像素、显示或隐藏边线。有选区时，画、擦、清除、填充都只作用在选区里。
- **油漆桶**：颜色容差、缝隙闭合（0 到 10 像素，出厂是关）、看哪里的颜色（所有图层合起来，或者只看当前图层）。做法见 §3.5。
- **移动和自由变换**：移动工具，或者用别的工具时按住 Ctrl 拖动；有选区时只动选中的部分，选区跟着走。Ctrl+T 进入自由变换：拖角缩放（默认等比，按住 Shift 可以变形），拖边只拉一个方向，框内拖动是移动，框外拖动是旋转（Shift 每档 15°）；面板上有确定、取消、翻转、转 90°、复位。拖动中用快速采样，确定时用高质量采样重算一遍；像素每次都从进入变换时的原图算起，来回拖不会越拖越糊。不缩放、角度是 90° 整数倍时，结果是原像素的原样搬运，不经过插值。
- **图层**：保护不透明度、锁定、剪贴三个开关；合并可见图层、拼合成一层；填充前景色；白底变透明（把扫描的白底线稿变成透明底，处理后叠在白底上看起来不变）。当前图层锁定或者隐藏时不开始一笔，光标的圆环里多一道斜杠。
- **PSD 和 ORA**：打开、导出。打开时有没能照原样读进来的内容，会列出来告诉用户。打开这两种文件后按"保存"，会另起一个我们自己格式的文件名，不去覆盖原文件。
- **快捷键自定义**：一个列表对话框，点功能、按键，就改了；这个键原来绑着别的功能的话，那一个被解除。键位存在设置文件里，只写改过的。菜单上的快捷键提示跟着变。
- **按住工具键借用**：按住某个工具的键，画一笔，松开，回到原来的工具；只按一下不画，就是换工具。
- **颜色面板**：红绿蓝滑块、色相饱和度明度滑块、色板，出厂不显示。面板可以整组换到右边。
- **Wintab 笔输入**和**最小压力**：在"笔"菜单里切换，不用重启。出厂仍然用 Windows 的笔输入。
- **马克笔**（用户 2026-10-14 要求加的，F-031，做法见 §3.6）：叠涂不会越叠越深，不透明度只升到这一笔的浓度为止，颜色向新色过渡。第一版做成了"叠涂变深"，用户拿参照软件对比后当天改成现在这样。原来的"铅笔"按用户的意见改名为"笔"，起草和勾线都用它；设置文件里沿用原来的名字，调好的参数不丢。工具栏上面一行现在是笔、马克笔、喷枪、橡皮、油漆桶。马克笔的快捷键是 N。
- **笔当橡皮用**（用户试用后加的）：笔倒过来用橡皮那头，或者用笔身上的按键在驱动里把笔切成橡皮时，自动换成橡皮工具；切回笔尖时换回原来的工具。只在两笔之间换。Windows 笔输入看笔的"倒置""橡皮"两个标志位，Wintab 看驱动登记的光标类型（这块板子的驱动把 1 号登记为笔、2 号登记为橡皮）和"倒置"状态位。
- 大面积重画（平移、缩放、变换预览）和变换的重采样分给几个线程做；一笔带来的小块重画不变，仍在当前线程上立刻做完。

与规格不一致、需要用户知道的地方：

- **图层文件夹（F-055）没有做。** 它要动图层的数据结构、合成、撤销、图层面板和三种文件格式，移动和合并时的规则也有不少要拿主意的地方（一个图层上移时什么时候算"进了文件夹"、文件夹整体怎么移动）。这些更适合在用户实际用过一阵之后再定，所以从 M2 里拿了出来。PSD 和 ORA 里的图层组读入时展开成普通图层，并给出提示。
- **锁定只有两个开关**（保护不透明度、锁定），规格里写的是 4 个。
- **自由变换只有一种方式**：缩放、旋转、移动合在同一组手柄上。没有"扭曲"（四个角各自拖动的那种变形）。
- **没有做选项对话框（F-160）**：现有的设置都放在"笔"和"视图"两个菜单里，没有需要对话框的。
- **按住工具键借用的判定**是"按着的时候有没有用过"，不是规格里写的"按住超过 250 毫秒"。这样慢慢按一下不会被误当成借用。
- **选区的边线是不动的黑白虚线**，不是流动的那种。
- **选区的扩大和收缩一次固定 1 像素**，没有输入数值的地方。
- **移到画布外面的内容会被裁掉**：图层只保存画布范围内的像素。一次拖动或一次变换之内来回移动不会丢东西，确认之后出了画布的部分就没有了。
- **回车、Esc 和单按的数字键是固定的**，方向键也不能绑。
- 交换格式里保不住的东西：两种格式都是每通道 8 位；ORA 不保存剪贴和两个锁；PSD 保存剪贴和保护不透明度，不保存锁定；撤销历史、选区、当前图层都不保存。
- 读 PSD 时：图层组展开；蒙版、矢量蒙版、图层样式忽略；文字图层和智能对象只留像素；调整图层跳过；本程序没有的混合模式改成"正常"；用 ZIP 压缩像素的图层读不了（一个图层都读不出来时，读入合并后的图像）；CMYK、Lab、索引色、灰度的文件打不开，会说明是哪种模式。每一项都会列在打开后的提示里。
- JPEG 的读写（§5.2，P1）还没做。

仍然存在的问题：

- Wintab 的位置、中文输入法下的快捷键对话框、"笔当橡皮用"三项，修好后用户 2026-10-14 复测都没问题。Wintab 仍是可选项，出厂不启用。
- **改过之后的马克笔还没有用真笔画过。** 单元测试覆盖了它的规则（交叉处不变深、不透明度只升不降、换色时向新色过渡、颜色合法）。
- **这一轮的界面检查走的都是鼠标消息**，不是笔。笔输入的代码这一轮改过（为了让 Wintab 和 Windows 笔消息走同一条路），逻辑上与之前等价。用笔实际走过的只有三样：延迟回归、按住 Ctrl 拖动、选框的加选和减选。油漆桶、魔棒、套索、变换的手柄没有用笔点过，用的是鼠标消息。
- **"打开"和"导出"两个菜单命令没有在实际窗口里点过**（它们要经过系统的文件对话框，后台测不了）。PSD 的打开是用命令行参数验证的；导出只验证了写文件的函数（单元测试和与 GIMP 的互通）。没验证的是对话框这一段：在导出对话框里选了"Photoshop 文件"却没写扩展名时，系统补上的扩展名对不对；以及打开 PSD 后按"保存"是不是另起文件名。
- 铺满整张画布的图层做自由变换时，预览约每秒 26 次，能用但不算顺。
- 变换预览用的是快速采样，缩小时很细的线可能时有时无，确认后才是最终质量。
- 带软边的选区（魔棒选出来的）移动之后，原来的位置上会留下一圈很淡的痕迹。
- 整张 3000×2000 的选区扩大或收缩一次要约 0.35 秒；400×300 的选区感觉不到停顿。
- 油漆桶每次要按整张画布分配工作内存（每像素 2 到 3 个字节，没用到的部分不占物理内存）：最大画布上是 512 到 770 MB。3000×2000 的画布上点一下，单元测试里计时是 22 到 68 毫秒（缝隙闭合开得越大越慢）。
- M1 留下的问题没有变化：稳定器高档位的滞后、保存大画布时的内存、文件对话框不记位置。

开发中发现并修掉的问题：

- **变换预览太慢**：第一版在铺满的图层上每步 50 到 76 毫秒。原因是每一步都要把整层重采样、整张画布重新合成并重画，全在一个线程上。把重画和重采样按行、按分块分给几个线程之后是上表里的数字。
- **测试改了用户的设置**：头一批后台测试用的是用户自己的设置目录，把铅笔的快捷键改成了 Q、打开了颜色面板、稳定器调成了 0。发现后已经改回测试前的样子；之后的测试实例都用单独的设置目录。
- **对话框里的说明文字各自带一块灰底**：改成跟对话框一样的白底。
- **打开 PSD 后的提示**原先用系统的消息框，后台截图里只看到第一行字，后面的说明是空白（没有查清是真没画出来还是截图取不到）。换成了自己的说明窗口：带滚动条，文字可以选中复制，条目再多也不会把窗口撑大。换了之后三条说明都显示完整。
- **Wintab 下线画在上下颠倒的位置**（用户实测发现）：程序原先拿头几个数据包和系统光标的位置比对来猜纵轴方向，笔刚进感应范围时光标往往还停在别处（比如刚点过的菜单上），就猜反了，而且一猜定终身。改成照 Wintab 规范固定倒转纵轴（规范里数位板的原点在左下角），不再猜。
- **中文输入法开着时，快捷键对话框里绑不上字母键**（用户实测发现）：输入法先把按键截走了。主窗口在 M1 就关掉了输入法，这个对话框是另一个窗口，漏了。现在对话框和它里面的控件都不用输入法。用户已复测。
- **大笔刷严重卡顿**（用户实测发现：笔刷开到最大时马克笔几乎没法用，笔也卡）。原因在笔画引擎：样本之间的曲线被切成每段 2.5 像素的小段，每一小段都按一个完整的胶囊去算覆盖率，500 像素的笔每来一个样本就要把一个直径 500 的圆重算好几遍。笔每 5 毫秒送来一个样本，处理不过来就越积越多。改了三处：曲线小段的长度随笔刷半径放大（不小于半径的一半）；每一行只走胶囊实际覆盖的那一段像素，已经涂到这一段最大浓度的像素直接跳过；大面积时按分块分给几个线程。另外把显示重画分线程的门槛从 40 万像素降到 15 万。新增一个平时不跑的计时测试（`big_brush_timing`），视图 100%、3000×2000 画布上，每来一个样本的耗时：

  | 情形 | 改前：引擎 / 重画 | 改后：引擎 / 重画 |
  |------|------------------|------------------|
  | 笔，大小 500，每样本 5 像素 | 4.25 / 2.69 毫秒 | 0.87 / 2.18 毫秒 |
  | 马克笔，大小 500，每样本 5 像素 | 6.25 / 2.85 毫秒 | 0.96 / 2.22 毫秒 |
  | 马克笔，大小 500，每样本 20 像素（快速划过） | 15.08 / 2.26 毫秒 | 0.99 / 1.85 毫秒 |
  | 同上，视图缩到 56% | — | 1.01 / 2.63 毫秒 |
  | 笔，大小 10 | 0.01 / 0.07 毫秒 | 0.01 / 0.06 毫秒 |

  抬笔时把一整笔并入图层，大小 500 的一笔要 8 到 17 毫秒（改前 19 到 56 毫秒）。这些是核心模块的计时，没有在实际窗口里用笔复测。
- **马克笔边缘太糊**（用户实测发现，笔刷开得很大时）：软边宽度原先与"1 − 硬度"成正比，500 像素的笔在硬度 90% 时边缘糊出约 26 像素。改成与它的平方成正比（90% 时约 3.5 像素），马克笔出厂硬度改为 100%。边缘软硬仍在"边缘硬度"滑块上调，马克笔面板上加了一行提示。
- **PSD 里"隐藏"标志位的含义**：写这个模块时拿 GIMP 对照发现，规格书上对这一位的叫法和 GIMP 读写文件时的实际用法对不上，照字面实现的话图层的显隐会全反。按 GIMP 的实际用法做了，两个方向都验证过。

## 7. 风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 所选界面框架拿不到完整的笔数据（压力、亚像素坐标、历史样本） | M0 就卡住 | 笔输入不经过框架，直接向系统取；研究阶段写的记录器已经验证过这条路 |
| 延迟达不到合格线 | M0 验收不过 | 合格线取的是对照软件的水平，余量大；最简程序实测约 3 毫秒，说明系统本身不是瓶颈 |
| 处理器渲染在旋转视图、大笔刷、高分辨率屏上不够快 | 导航卡顿 | 只重采样脏区域；拖动中用快速采样、停下后补高质量采样；实在不够再考虑图形处理器，但不预先为它设计 |
| Wintab 驱动之间的差异 | 部分数位板没有压感 | 首版只做 Windows 指针输入；Wintab 放 P1，并保留接口选择开关 |
| 第三方库的许可证与 GPL-3.0 不兼容 | 不能发布 | 引入任何依赖前核对许可证；带"非商业"条款的库一律不用 |
| 混色效果没有实测目标 | 做出来不好用 | 放在 P1，先发一个不含混色的可用版本 |
| 所有测量都来自合成输入，没有真实的笔和主观评分 | 指标都达到了但手感不对 | 文档里已写明；M0 做出来后请用户实际画几笔，这比任何指标都直接 |
| 范围蔓延 | 做不完 | 功能列表里已标出"不做"；新增功能必须先进功能列表 |
| 净室纪律 | 法律风险 | 开发阶段只读 `docs/spec/`；`analysis/` 不入库、不进入开发环境的上下文 |

## 8. 需要用户决定的点

1. 技术选型（§1.4）：我建议方案二（Rust 加 Windows 原生接口、界面自绘），代价是只支持 Windows。
2. 像素格式用 15 位定点（质量好、内存翻倍）还是 8 位（简单、省内存）。我建议前者。
3. 原生格式用"ZIP 加 JSON 加逐层 PNG"是否可以接受。
4. 验收合格线取"不差于 GIMP 和画图"是否可以接受。
