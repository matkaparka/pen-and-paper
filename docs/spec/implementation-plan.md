# 实现方案（阶段 3 规格，待用户审阅）

状态：已批准，2026-10-13。

**用户已于 2026-10-13 批准，按文中的建议执行。** 用户同时给出了一句定位，作为今后取舍的总原则：
参照软件好用，是因为它只处理绘画的问题，不处理其他美术方面的问题，所以能兼顾绘画上的专业和好上手。
新软件照此办理：只做绘画。任何"顺便也能做"的功能，默认不做。

采用的决定：技术选型用方案二（Rust 加 Windows 原生接口、界面自绘）；像素格式 15 位定点；原生格式为 ZIP 加 JSON 加逐层 PNG；验收合格线取"不差于 GIMP 和画图"。新软件暂定名"纸笔"（`zhibi`）。

本文只依据行为规格（[feature-list.md](feature-list.md)、[interaction-analysis.md](interaction-analysis.md)）和公开文献来设计。
参照软件的内部实现没有被读取或转写；文中所有算法都是我们自己的设计，出处见 §4 的文献表。

设计取向来自用户的要求：**用着容易、结构简单，性能够用即可**。凡是"更快但更复杂"和"够用且简单"之间的选择，默认选后者。

## 1. 技术选型

下面的事实来自 2026-10-13 对各项目官方文档、发布页和源码仓库的查询（由一个后台助手完成，我没有逐条复核原文）。标"未核实"的是当时没能从一手来源确认的。动工前，选中方案涉及的条目要再核对一次。

### 1.1 查到的事实

| 维度 | 甲：C++ 加 Qt 6 | 乙：Rust 加 winit 加界面库 | 丙：SDL3 | 丁：直接用 Windows 原生接口 |
|------|-----------------|---------------------------|----------|------------------------------|
| Windows 上的笔输入后端 | Windows 指针输入为默认；Wintab 要通过私有接口开启，没有兼容性承诺 | 只有 Windows 指针输入；winit 不打算内置 Wintab | 只有 Windows 指针输入；Wintab 列在 3.6 的计划里 | 两种都能做，都要自己写 |
| 压力 / 倾斜 | 有 / 有 | 稳定版 0.30 只有压力；倾斜只在 0.31 测试版里 | 有 / 有 | 有 / 有 |

| 许可证 | 主要模块 LGPL-3.0 或 GPL-3.0，少数附加模块仅 GPL-3.0 | winit Apache-2.0；wgpu、egui、softbuffer 为 MIT 或 Apache-2.0；iced MIT；Slint 可选 GPL-3.0-only | zlib | 系统接口，适用 GPL 的系统库例外 |

| 跨平台 | 好 | 好 | 好 | 仅 Windows |

两点对选型影响最大：

1. **没有一个现成框架能直接满足"两种笔接口、全部历史样本、可切换"**。Qt 最接近，但 Wintab 靠私有接口，而用 Qt 的两个成熟绘画程序最后都自己写了数位板代码。也就是说，无论选哪个，笔输入这一层多半要自己写。
2. **笔输入这一层我们已经写过并测过**：研究阶段的 `pentap` 用系统原生接口取到了全部历史样本和 Wintab 设备信息，最简画线程序的跟随延迟约 3 毫秒。

### 1.2 三套候选方案

**方案一：C++ 加 Qt 6 Widgets**

- 好处：界面控件最全，高分屏和输入法现成，跨平台，先例最多。最快做出"功能齐全的界面"。
- 代价：依赖大，发布时要带一组运行库，与"结构简单"的方向相反；Wintab 仍要绕开框架自己接；C++ 的内存安全要靠自律。

**方案二：Rust 加 Windows 原生接口，界面自绘**

- 做法：窗口、菜单、对话框、文字输入框用系统原生控件（中文输入法因此直接可用）；画布和左侧面板自己画；笔输入直接向系统取；处理器渲染，按脏区域贴到窗口。分块存储、笔画引擎、文档、文件读写写成不依赖平台的独立模块。
- 好处：结构最简单，成品是一个不带运行库的可执行文件，这与参照软件给人的印象一致；笔输入完全可控，两种接口都能做；没有许可证问题；研究阶段的输入代码和测量工具可以直接沿用。
- 代价：只支持 Windows；面板里的控件要自己写（数量有限：滑块、色环、图层列表、大小表、工具盘、笔画预览）；高分屏适配要自己处理。
- 跨平台的余地：核心模块不依赖平台，将来换一个平台层即可，但界面层要重写。

**方案三：Rust 加 winit 加 softbuffer，再配一个界面库（Slint 或 egui）**

- 好处：跨平台；部件小而宽松；softbuffer 支持按脏区域提交。
- 代价：界面库都不传递完整的笔数据，所以仍要在框架旁边另接一条原生输入通道，等于同时承担方案二的输入工作和框架的学习与升级成本；egui 在 Windows 上的输入法问题对中文用户是实际障碍；这些库版本变动快。

SDL3 没有列为候选：它在 Windows 上取不到被合并的历史样本，目前没有 Wintab，也不带界面控件，三项都要自己补。

### 1.3 按评估维度比较

| 维度 | 方案一 | 方案二 | 方案三 |
|------|--------|--------|--------|
| 笔输入（两种接口、全部样本） | 指针输入好；Wintab 要自己接 | 都自己接，已有可用代码 | 都要在框架外自己接 |
| 低延迟渲染 | 够用 | 够用，已实测约 3 毫秒的下限 | 够用 |
| 许可证兼容 | 兼容 | 无依赖，最干净 | 兼容 |
| 跨平台前景 | 最好 | 只有核心可移植 | 好 |
| 生态与可维护性 | 成熟稳定 | 依赖最少，但界面代码全靠自己维护 | 库多但变动快 |
| 结构简单（用户的首要要求） | 最重 | 最轻 | 中等 |
| 做出第一个可用版本的工作量 | 界面省事，输入要补 | 界面费事，输入现成 | 两头都要做 |

### 1.4 建议

建议**方案二**。理由按分量排：

1. 用户的首要要求是结构简单，方案二的成品形态最接近这一点。
2. 最难、最影响手感的一层（笔输入和低延迟显示）在这个方案里风险最低，因为已经做过并量过。
3. 首批范围里需要自绘的控件只有六种，而首版又是固定布局，自绘界面的工作量是有界的。

它的主要代价是只支持 Windows。如果你希望将来能在其他系统上用，或者更看重尽快把界面铺开，方案一更合适。这是需要你决定的事。

## 2. 架构

自上而下六层，每层只依赖它下面的层。

```
界面层        面板、菜单、快捷键、对话框
视图层        画布视图：缩放/旋转/翻转的变换，脏区域的显示
文档层        文档、图层树、选区、撤销栈
笔画引擎      稳定器 → 插值 → 笔触绘制
分块存储      稀疏分块、写时复制
平台层        窗口、笔输入、文件、剪贴板
```

### 2.1 输入层（平台层的一部分）

- 把系统送来的笔事件统一成一种样本：时间戳、位置（浮点，窗口坐标）、压力（0 到 1）、阶段（悬停、落笔、移动、抬笔）。
- 一条系统消息里如果带着多个被合并的历史样本，全部取出，按时间顺序逐个交给上层，不丢弃。
- 事件一到就处理，不攒到下一帧。
- 启动时为画布窗口关闭系统的笔长按和轻拂手势（它们会推迟落笔的判定）。
- 修饰键的两条规则在这一层实现：按住临时切换工具；"修饰键 + 按键"之后 300 毫秒内忽略修饰键（F-151）。
- 首版只接 Windows 指针输入；Wintab 作为第二个后端在 P1 加入，两者产出同一种样本，上层不感知差别。

### 2.2 笔画引擎

一条笔画的处理顺序：

1. **坐标变换**：窗口坐标经视图变换的逆变换得到画布坐标。
2. **稳定器**：见 §3.1。
3. **插值**：把稀疏的样本连成平滑路径，见 §3.2。
4. **笔触绘制**：沿路径按固定间距落下圆形笔触，见 §3.3。
5. **报告脏区域**：返回这一段碰到的分块列表，交给视图层重画。

所有笔刷类工具（铅笔、喷枪、橡皮、选区笔，以及 P1 的混色笔刷）都是这一个引擎的参数预设（F-010）。

### 2.3 画布与分块存储

- 每个图层是一张稀疏的分块表：键是分块坐标，值是一个 64×64 像素的分块。没画过的地方不占内存。
- 像素格式：预乘透明度的 RGBA，每通道 16 位整数中取 15 位定点（数值 0 到 32768）。好处是低浓度反复叠涂时不会像 8 位那样出现色带，代价是内存翻倍。分块边长和这种定点格式都取自开源项目 MyPaint 的公开做法（前者已核实，后者未核实，见 §4）。
- 分块是写时复制的：撤销栈和恢复文件只需要保留对旧分块的引用，不必整层拷贝。
- 画布边长上限首版定为 16384 像素（F-172）。

### 2.4 渲染管线

- 全部在处理器上完成，不依赖图形处理器。依据有两条：研究阶段没有在参照软件里发现任何图形处理器接口的痕迹（这是推断，不是确证），而它实测比两款对照软件都跟手；我们自己"收到事件立刻用系统绘图接口画"的最简程序，跟随延迟约 3 毫秒。所以这条路对"够用"有很大余量。
- 每个分块缓存一份"所有可见图层合成后"的 8 位显示结果。笔画只让它碰到的分块失效。
- 视图层把失效分块覆盖的屏幕区域按当前的缩放、旋转、翻转重新采样，只把这块区域提交给窗口。
- 缩小显示时使用逐级减半的缓存，避免每次都从原始分辨率采样。
- 正在画的那一笔先画在一张临时的笔画层上，显示时叠在当前图层上方；抬笔时并入图层。这样"同一笔内不重复加深"和"撤销一整笔"都很直接。

### 2.5 图层合成

- 图层树自下而上合成，支持不透明度、可见性、混合模式；P1 加剪贴组、文件夹、锁定。
- 混合模式的公式采用 W3C《Compositing and Blending Level 1》这份公开标准，首版 8 种：正常、正片叠底、滤色、叠加、变暗、变亮、线性减淡、差值。

### 2.6 撤销系统

- 撤销栈里的每一项是一条命令。绘制类命令保存"被改动的分块在改动前的版本"；结构类命令（新建、删除、排序图层等）保存逆操作所需的信息。
- 文档记住上次保存时栈顶的位置；栈顶回到这个位置时，未保存标记消失（F-002）。
- 首版全部放在内存里，按占用设上限，至少保留 100 步。P1 把较旧的分块写到临时文件（F-182）。

### 2.7 界面层

- 固定布局：左侧两列面板，其余全部是画布；首版不做面板拖放。
- 需要自己画的控件：色环、带数值的滑块、图层列表、笔刷大小表、笔画预览。
- 首版的菜单项总数控制在 60 以内，会打开模态对话框的命令不超过 6 个。
- 所有设置（键位、工具预设、大小表、窗口状态）存成用户目录下的文本文件，删掉即恢复出厂（F-163）。

## 3. 关键算法：我们自己的设计

### 3.1 稳定器

行为目标见 F-016 至 F-018。设计：

- 档位 N（0 到 15）对应一个长度为 N+1 的滑动窗口，对窗口内样本的位置和压力分别取等权平均，平均值作为输出点。
- 落笔时：位置窗口全部填成落笔点（线从落笔处开始，不会从别处飞过来）；压力窗口全部填零（所以线头自然渐细，F-018）。
- 开发中的修正（M0）：压力窗口取 N+3 个样本，比位置窗口多 2 个（档位 0 不平滑）。原因是两个窗口等长时，仿真得到的渐细长度只有规格实测值的一半左右；多 2 个样本后，档位 1 / 2 / 3 / 5 / 8 / 15 的仿真值为 11 / 13 / 15 / 19 / 24 / 38 像素，规格里的参照值为 11 / 13 / 14 / 18 / 24 / 39。
- 抬笔时：把窗口里还没有体现到输出上的原始样本依次补画出来，一直画到抬笔位置（F-017）。做法是每一步从窗口尾部去掉一个最旧的样本再取平均，直到窗口只剩最后一个样本。
- 滑动平均是教科书上的标准滤波器。选它而不是自适应滤波器，是因为行为规格要求"同一档位永远是同一种手感"，而且实测的保留比例与它吻合。
- 已知缺口：参照软件实测的延迟增长比这个模型的理论值小。首版先按本设计实现，用 `strokebench` 测出我们自己的延迟曲线后再决定是否调整权重（例如让较新的样本权重更大）。
- 更强的档位（F-019，P2）另行设计，候选是公开的"拉绳"模型：笔刷被一根固定长度的绳子拖着走，笔在绳长范围内移动时笔刷不动。

### 3.2 样本间插值

- 相邻的稳定器输出点之间用向心 Catmull-Rom 样条连接。向心参数化不会在尖角和密集样本处产生自交或尖刺，这是公开文献里的结论（见 §4）。
- 沿曲线按弧长等距取点，间距取当前笔触直径的一个固定比例；压力在样本间线性插值。
- 最后一段（最新的两个点之间）先按直线画，等下一个点到来后再用曲线替换。这样墨迹不必等下一个样本就能跟到笔尖。

### 3.3 笔触绘制

- 笔触是一个圆：到圆心的距离小于半径处完全覆盖，边缘在约一个像素宽的范围内线性过渡到零。"边缘硬度"参数把这个过渡带加宽。
- 半径 = 最小半径 +（最大半径 − 最小半径）× 压力（F-011、F-013）。半径可以小于一个像素，此时靠覆盖率表现，所以细线是渐渐变淡而不是突然断掉。
- 同一笔之内，每个像素的覆盖率取各笔触的最大值，而不是累加；抬笔时再按浓度并入图层。这样一笔之内来回涂不会越涂越深。
- 橡皮是同一个过程，只是并入时做的是减少不透明度。

### 3.4 混色笔刷（P1）

- 行为规格里这一项没有实测数据（F-023），所以不以参照软件为目标，只要求"在两块颜色之间来回涂能得到平滑过渡"。
- 设计：笔刷带着一个"当前载色"。每落一个笔触，先读取笔触下方画布的平均颜色，按"混色"参数把载色向它靠拢，再按"持续"参数决定载色保留多少，最后用载色绘制。"稀释"参数降低绘制时的不透明度。
- 颜色混合首版在线性光 RGB 里做。基于颜料光谱的混合（Kubelka-Munk 一类）效果更像真颜料，但复杂得多，留作以后的可选项。

### 3.5 带缝隙闭合的填充（P1）

- 目标见 F-071：线稿有小缺口时不漏色。
- 设计：先对"线"的区域做距离变换，得到每个空白像素到最近线条的距离；泛洪填充时，不允许从"距离大于容差的区域"穿过"距离小于容差的瓶颈"进入另一片区域。实现细节在动工前参照公开的开源实现再定。
- M2 实际做成的样子（`core/src/fill.rs`）：
  1. 先做普通的泛洪，得到与起点相连、颜色在容差内的区域。
  2. 算出区域里每个像素离最近的边界有多远（倒角距离）。比"缝隙宽度的一半"更宽敞的地方，是一个比缝隙大的圆放得进去的地方；只保留其中包含起点的那一片。
  3. 剩下那些窄的地方（墙角、尖端、窄缝）按"分水岭"的办法分给相邻的宽敞区域：从宽到窄同时向外漫，在瓶颈最窄的地方相遇，缺口就在那里被封住。只挨着一片区域的窄地方整个归它，所以墙角和尖端不会留下没填到的边。
  4. 软边：从区域边界向线条里探，颜色还在持续远离起点色的那几个像素按比例算进来，探到颜色不再变的地方（线芯）为止。这样填色一直铺到线芯跟前，线的抗锯齿边底下不留浅色的缝，线芯也不会被吃掉。
  - 起点本身就落在比缝隙还窄的地方时，圆的大小减到当地宽度的一半，细长的区域照样能作为细长的区域填上。
  - 这套做法是照公开文献里的想法自己搭的（"困球"分割、带标记的分水岭、倒角距离），出处写在源文件开头，凭记忆写的，细节没有逐条核对。

### 3.6 马克笔（F-031）

- 目标：叠涂不越叠越深，颜色平滑地向新色过渡。用户 2026-10-14 拿参照软件的马克笔和我们的第一版对比，参照软件两笔交叉处没有变深。
- 公开资料对参照软件马克笔的描述（只有行为，没有算法）：Krita 手册说它的"Marker"模式"只有这一笔比图层上已有的更不透明时才提高不透明度，并混合颜色，就像参照软件的马克笔"；Drawpile 的开发日志说它的"Marker"模式"只提高不透明度，但总是混合颜色，和参照软件的马克笔一样"。
- 我们的做法：笔刷引擎已经保证一笔之内同一个像素只按覆盖率最大的那一次计（§3.3）。落笔时，设这一笔在某像素上的强度为 a（覆盖率乘浓度），原有像素的不透明度为 Da：
  - 不透明度 = max(Da, a)。比原有的淡的笔落上去，不透明度不变；永远不会越叠越浓。
  - 颜色 = 普通覆盖（source-over）时会得到的那个颜色，即预乘的"a·笔色 + (1−a)·原色"除以"a + (1−a)·Da"。空白处就是笔色；同色叠涂颜色不变；换色时按 a 的大小向新色过渡。
  - 两项都是我们按上面的行为描述自己定的，没有参照任何一家的实现。
- 保护不透明度时：颜色照上面算，不透明度保持原样。
- 出厂参数：大小 30、粗细不随压力变（最小大小 100%）、浓度 100%、最小浓度 30%（压力只管浓淡）、边缘硬度 100%（硬边，上色时边缘干净；用户反映 90% 时大笔刷边缘太糊，见下一条）。
- 边缘软硬对所有笔刷都可调（"边缘硬度"滑块）。软边的宽度与"1 − 硬度"的平方乘半径成正比：硬度 90% 时只有半径的 1%，500 像素的笔边缘只糊三四个像素；硬度 0 时从圆心一直软到边上。原先是一次方，大笔刷上硬度 90% 就糊出二十多个像素，滑块能用的范围全挤在最右边。
- 第一版（同一天）用的是"叠色"：颜色与已有颜色相乘，叠涂变深。用户对比之后改成了现在的做法。
- 不带拖色（画的时候把底下的颜色带着走）。有的用户把参照软件的马克笔说成带"持续"的混色笔，这类效果归 F-023 混色笔刷。

### 3.7 一般映射的重采样（0.2）

自由变换的扭曲、网格和液化都不是仿射变换，需要一条更一般的重采样路：

- 仍然反向映射：给每个目标像素的中心找到它在源图上的位置，在那里插值。仿射变换照旧走原来那条路（整像素平移、翻转、转 90° 照搬像素），不受影响。
- 一般映射写成一个接口：给一个目标分块，把块内每个像素中心对应的源坐标填进一张 65×65 的表（多一行一列，用来算相邻像素间源坐标的差）。没有对应源点的像素（网格外面、透视里"地平线"后面）填一个"没有"，结果是透明。
- 采样：快速档双线性；高质量档 Catmull-Rom，并按这个像素处的局部缩小倍数（由相邻像素的源坐标差算出来）分子采样点，规则和仿射时一样（每个方向不超过 16 个）。
- 选区：和仿射时一样，选中的部分浮起来变换，叠回没选中的部分上；选区自己当一张只有透明度的图，走同一个映射，所以选区的边和内容的边对得上。
- 源图里画布以外的像素当作透明，结果裁到画布内，这两条也和仿射时一样。

### 3.8 扭曲、斜切与网格（F-080 补全，0.2）

外框用三层数据描述，从里到外：

1. **网格**：外框上 4×4 个点（3×3 格），每个点存一个偏移，单位是变换前的像素，坐标轴跟着外框自己走。
2. **四个角**：每个角存一个偏移，同样在外框自己的坐标里。
3. **外框的位置**：中心、两个方向的缩放、角度，就是 M2 的那一套，移动、缩放、旋转、翻转、转 90° 都只改这一层。

所以先扭曲再旋转，扭曲跟着转；先旋转再扭曲也一样。复位把三层都清零。

- **扭曲**（拖角）：把这个角的偏移改成让角正好落在指针下（扣掉按下时指针离角的那几个像素）。四个角定出一个四边形，源矩形到它的映射是射影变换，用 Heckbert（1989）的"正方形到四边形"闭式解求出 3×3 矩阵，和外框位置的仿射矩阵乘起来，再求逆，逐像素反算源坐标。分母小于等于零的像素在地平线后面，没有源点。
- 拖到会让四边形凹进去或者自己交叉的位置时，角停在最后一个合法的位置：凹四边形没有对应的射影变换。
- **斜切**（拖边）：这条边的两个角沿着这条边原来的方向一起滑动，滑动的量是指针移动量在这个方向上的投影。
- 四个角的偏移恰好构成平行四边形时（只做过斜切），映射仍是仿射的，交给仿射那条路。
- **网格**（拖点）：网格上一点的位置 = 外框位置 ∘（射影变换 (u, v) + S(u, v)），S 是 4×4 个偏移的 Catmull-Rom 插值曲面（两个方向分别插值；边上缺的邻点按直线外推），所以拖一个点，曲面正好经过它，附近平滑地跟着弯。四个角上的网格点也是网格点，拖它们改的是网格偏移，不是角。
- 网格的映射没有闭式的逆。做法是把源区域（外框四周多留两个像素给插值核）切成小格，每个格点正向算出它在画布上的位置，每一格拆成两个三角形，按三角形在目标上光栅化：目标像素落在哪个三角形里，就用重心坐标在三个顶点的源坐标之间插值。格子按目标上不超过约 16 像素一格来切（每个方向最多 1024 格）。网格弯得叠起来时，后画的三角形盖住先画的。
- 自由方式下按住 Ctrl，拖角是扭曲、拖边是斜切，和面板上选"扭曲"一样；Ctrl 只在按下的那一刻看。
- 面板上的读数照旧是外框的宽、高、角度；做过扭曲或网格的，后面注明。

### 3.9 液化（F-083，0.2）

- **位移场**：开始液化时存下当前图层的原图（分块共享，不复制）和选区。之后只改一张位移场 D：每个像素一个二维偏移（两个 32 位浮点数），表示"这个像素从原图上 p + D(p) 处取色"。位移场按 64×64 分块稀疏存储，没碰过的地方没有分块，当作零；一个分块 32 KB，和图层的一个分块一样大。画面 = 原图按 D 重采样，D 为零的像素直接照搬原图，所以复原到底时一位不差。
- **笔刷形状**：半径 R 内的权重 w(d) = 强度 × 压力 × (1 − (d/R)²)²，圆心最强，到边上平滑地降到零，没有硬边。有选区时再乘上这个像素的选中程度：没选中的像素不会动（但选区里的像素可以从选区外取色）。
- **各种方式**：都写成"新画面在 p 处的颜色 = 旧画面在 q(p) 处的颜色"，于是 D'(p) = q(p) + D(q(p)) − p，D 在 q 处用双线性插值取。读的是这一下之前的 D（分块写时复制，取一个快照不费事）。
  - 推：q = p − w·Δ，Δ 是笔这一下移动的距离。一次移动超过 R/4 时拆成几步。
  - 顺时针转、逆时针转：q = c + Rot(∓θ·w)(p − c)，c 是笔刷中心；θ 随时间增长，强度 100% 时圆心处每秒转约 180°。
  - 收缩、膨胀：q = c + (p − c)·(1 ± k·w·dt)，强度 100% 时圆心处每秒约缩放一倍。
  - 复原：D'(p) = D(p)·(1 − r·w·dt)，强度 100% 时圆心处每秒拉回约 95%；小于 1/256 像素的偏移直接归零。
  - 推只看移动，其余四种看时间：笔按着不动也一直在起作用。用鼠标时按着不动不会有新的消息，所以按着期间每 15 毫秒补一个当前位置。
- **预览**：每一下只重算它碰到的那块（双线性），换进图层里显示，屏幕上也只重画那一块。
- **落实**：D 不为零的分块用高质量档（Catmull-Rom，按局部缩小倍数超采样）重算一遍，换进图层，记一个撤销步骤；其余分块照旧共用。
- **一次液化里的撤销**：每一笔开始前存一个 D 的快照（同样是分块共享），撤销、重做在快照之间来回；撤到第一笔之前再撤一次，等于取消这次液化。
- 保护不透明度：透明度保持原样，只有颜色跟着动。锁定、隐藏的图层不能液化。
- 推出画布的像素在落实后丢掉（与移动、变换相同）。

### 3.10 调色与模糊（F-095，0.2）

- 进入时存下当前图层的原图；拖滑块时整层从原图重算（按分块分给几个线程），换进图层预览；确定时记一个撤销步骤，取消时换回原图。参数每次进入都从零开始，不存进设置。
- 颜色按图层里存的值（sRGB 编码，15 位）算，先除掉透明度，算完再乘回去；透明度不变（模糊除外）。有选区时按选中的程度在原色和新色之间过渡。
- **色相/饱和度/明度**：三个滑块，色相 −180° 到 180°，饱和度、明度 −100 到 100。色相在 HSL 里转；饱和度把 HSL 的 S 乘 (1 + 饱和度)；明度为正时向白色过渡（c + (1 − c)·明度），为负时向黑色过渡（c·(1 + 明度)）。
- **亮度/对比度**：两个滑块，−100 到 100。亮度的规则同上面的明度；对比度以中灰为轴改斜率，斜率 = tan((对比度 + 1)·π/4)，对比度为零时斜率是 1。
- **模糊**：一个滑块，半径 0 到 100 像素。高斯模糊，σ = 半径 / 2，用三次方框模糊逼近（Wells 1986），横竖分开做，按分块的一行（或一列）一组处理，工作内存是图层的一份拷贝加几条行缓冲。方框的宽度用"扩展方框"（Gwosdek 等 2011）：两头各多一个权重不足 1 的像素，三次的方差之和正好是 σ²；宽度只取整数的话，半径 1 时根本不模糊，拖滑块时模糊程度也是一跳一跳的。在预乘值上模糊，透明的边上不会出现深色的边。画布的边缘按边上的像素向外延伸，铺满的图层模糊后边上不会变透明；画布以内透明的地方就是透明。保护不透明度时透明度保持原样。

### 3.11 图层文件夹（F-055，0.3）

**数据**：图层仍是一个自下而上的列表，每一层多记一个嵌套深度。文件夹自己占一行；它里面的东西是紧挨在它下面（序号更小）、深度比它大的那一串。这和 PSD 存组的方式一样（PSD 是用"组开始""组结束"两条记录夹住，我们用深度），所以现有按序号办事的代码大多不用改。图层分三种：像素图层、文件夹、填充图层（§3.13）。

从上往下看列表，深度必须满足：最上面一行是 0；下一行的深度不超过这一行加 1，而且只有这一行是文件夹时才能加 1。每个操作都保持这一条；读文件时不满足的（坏文件）照这一条修正。

**合成**（每个分块各做一遍，从下往上）：

- 同一层级的兄弟按从下往上的顺序叠到一个累加器上。
- 普通文件夹（"隔离"）：里面的东西先叠到一张透明的底上，合出来的结果再像一个图层那样，按文件夹的混合模式、不透明度和蒙版叠上去。
- 穿透文件夹：里面的东西直接叠在累加器的一份拷贝上，然后累加器 = 累加器与拷贝按"不透明度 × 蒙版"过渡。不透明度 100%、没有蒙版时，等于没有这个文件夹。这是 PS 的"穿透"，也是 W3C 合成规范里"不隔离"的意思；GIMP 2.10 以后的"穿透"也是这样（实现后用 GIMP 对照）。
- 隐藏的文件夹，里面的东西一律不画。
- 剪贴：剪贴的底是同一个文件夹里、它下面最近的那个不剪贴的兄弟；文件夹也可以当底（用它合出来的透明度），也可以剪贴到下面的图层上。

**操作**（下面说的"上""下"都是图层列表上看到的方向）：

- 新建图层：当前是展开的文件夹时，放进它里面的最上面；否则放在当前图层上面，和它同一层级。
- 新建文件夹：空的，放在当前图层上面。放进新文件夹（Ctrl+G）：在当前图层的位置建一个文件夹，把当前图层（是文件夹的话连里面的一起）放进去。
- 上移：当前图层已经是所在文件夹里最上面的，就移出文件夹，放到文件夹上面；上面紧挨着的兄弟是展开的文件夹，就进到它里面的最下面；否则和上面的兄弟（连同它里面的东西）对调。下移反过来：已经是最下面的就移出文件夹放到它下面；下面的兄弟是展开的文件夹就进到它里面的最上面；否则对调。这样只用两个按钮就能把图层挪进挪出任何文件夹。
- 拖动排序：在图层列表里按住一行拖动，松手的位置决定放到哪里：落在一行的上三分之一，放到这一行上面；下三分之一，放到这一行下面（这一行是展开的文件夹时，放进它里面的最上面）；落在文件夹那一行的中间，放进文件夹里面的最上面。文件夹不能拖进自己里面。
- 删除、复制文件夹：连里面的一起，一个撤销步骤。
- 向下合并：当前是文件夹时，把它合成一个像素图层（按"隔离"合成，名字和位置不变）；当前是图层而下面的兄弟是文件夹或填充图层时不能合并。合并可见图层、拼合按树合成；合并之后空了的文件夹去掉。
- 能不能画：当前图层是像素图层、看得见、没锁，而且它外面的每一层文件夹都看得见、没锁。文件夹锁定就是里面的东西都锁定。
- 移动工具、自由变换在当前是文件夹时，对里面所有的图层（像素和蒙版）用同一个变换一起变；液化、滤镜、油漆桶对文件夹不能用。
- 撤销：挪动、进出文件夹记成一个"重新排列"（新旧两套顺序和深度），建立、删除照旧记"有无"。

### 3.12 图层蒙版（F-058，0.3）

- 每个图层、填充图层、文件夹最多一个蒙版：单通道、15 位、按 64×64 分块写时复制，和图层像素一样；分块以外的地方取一个默认值（全白或全黑），这和 PSD 里蒙版的"默认颜色"是一回事。另有一个"停用"开关。
- 合成时，这一层（或者文件夹合出来的结果）的像素都乘上蒙版的值（预乘的四个通道一起乘）。
- **编辑对象**：图层那一行上有一个"蒙版"开关，打开时编辑的是蒙版。画笔、喷枪、马克笔把蒙版往"前景色的明度"（0.299 R + 0.587 G + 0.114 B）推，强度是覆盖率乘浓度；橡皮往白推；清除是全部变白（全部显示），填充前景色是全部变成前景色的明度。都受选区限制，都是一个撤销步骤。画的过程中预览直接作用在蒙版上。
- 蒙版是编辑对象时，油漆桶、液化、滤镜不能用（圆环里有斜杠、菜单项不起作用）。
- 添加蒙版：没有选区时全白；有选区时选中的地方白、其余黑。删除蒙版。应用蒙版：把蒙版乘进像素再删掉蒙版（只对像素图层）。停用蒙版：合成时不算它，再点一次恢复。
- 移动、变换时蒙版跟着图层一起变（蒙版当作一张只有透明度的图，走和像素相同的变换）。

### 3.13 填充图层（F-061，0.3）

- 一种不存像素的图层：合成时按参数在每个分块里现算，铺满整张画布，形状由它的蒙版决定。
- 纯色：一个颜色，合成时现算。
- 渐变、图案（2026-10-15 改）：0.3 不自己算。PS 存 PSD 时会把填充图层画好的像素一起存进去，就显示这份像素；没有像素的显示成透明。读入时在说明里交代，存回 PSD 时描述符和像素都原样不变。原因：PS 的渐变有"平滑度"等参数，插值方式没有公开的规范，这台机器上也没有 PS 可以对照，自己算出来的结果没法验收。
- 从 PSD 读进来的填充图层记着原始的描述符；没改过就原样写回去，PS 里还是同一个填充图层。改过颜色的纯色填充按规范重新写一个纯色描述符。
- 纯色填充可以改成前景色；任何填充图层都可以栅格化成像素图层（蒙版保留）。填充图层本身不能画，可以画它的蒙版。

### 3.14 图层样式（F-062，0.3）

**数据**：图层多记一份"样式"：PS 原来的 `lfx2` 块（有旧版的 `lrFX` 也一起）原样存着，存回 PSD 时写回去；从 `lfx2` 里读出本程序会画的几种效果的参数；一个总开关（PS 的 `masterFXSwitch`）。

**画法**：效果只看图层的形状 A（像素的透明度乘蒙版），文件里的距离、大小都先乘上"效果缩放"（`Scl `）。

- 投影：A 沿光的反方向平移"距离"（角度 θ 是光照来的方向，0° 从右边来，90° 从上面来，投影往反方向落），扩张"大小 × 扩展%"，再按"大小 × (1 − 扩展%)"模糊；乘效果的不透明度，用效果的颜色和混合模式叠在图层下面。"图层挖空投影"（默认开）时再乘 (1 − A)。
- 外发光：A 扩张、模糊同上，不平移；"范围"把透明度往上拉（范围越小发光越实）；叠在图层下面，同样被图层自己挖空。
- 内发光（从边缘发）：1 − A 扩张"大小 × 阻塞%"、模糊，乘 A；范围同上；叠在图层上面。从中心发的反过来（用 A 收缩、模糊之后的 1 − 结果，乘 A）。
- 模糊用高斯近似（三次方框）。"大小"和高斯宽度的换算、"范围"的确切作用，PS 没有公开；拿用户文件里 PS 存的合并图像校准（在效果所在的地方，从 PS 的结果和不带效果的结果反推出效果的透明度，和我们算的比），校准结果和剩下的差写进实测结果。
- 叠法（一个图层）：先把投影、外发光按各自的混合模式叠在下面的东西上，再叠图层本身（它自己的混合模式），再叠内发光；最后整体和原来的样子按图层的不透明度过渡（同穿透的组）。剪贴在这个图层上的图层，底还是图层自己的透明度。
- 算一个图层的效果要对整层做几次方框模糊，大图层上要几百毫秒，所以结果按图层存起来：图层的像素、蒙版或样式变了才重算（分块表和蒙版各带一个改动编号，编号没变就不重算）。正在画的那一笔落笔之前，效果不跟着变。
- 不画的：别的效果、组上的样式；对比曲线不是直线的、带杂色的、用"精确"手法的发光，按直线、无杂色、柔和近似画。都在读入时的说明里交代。

**存与合并**：PSD 原样写回（总开关改过的，把 `lfx2` 里那个开关的字节改掉）；原生格式存原始块（Base64）和开关，读的时候重新解析；ORA 没有样式，导出时不带。向下合并、合并可见图层、拼合时效果画进结果（和 PS 一样）。

### 3.15 画布外的内容（F-063，0.3）

- 图层的像素可以在画布外。保留的范围是画布四周各再加一个画布的宽和高（3×3 个画布大），读入时更远的部分裁掉并说明。
- 读 PSD、ORA、原生格式时不再按画布裁，存的时候写全部内容（ORA 规范允许图层的位置是负数）。
- 移动、自由变换以保留的范围为界，画布外的内容跟着走；液化、滤镜只改画布里的，画布外的原样不动；画笔、填充、清除、选区仍只在画布里。
- 合成、导出 PNG、合并可见图层、拼合只看画布里（和 PS 一样）；向下合并保留两层在画布外的内容。

### 3.16 画板（F-064，0.3.1）

- PSD 里带 `artb` 块的组是画板。块里是一个描述符：画板的矩形 `artboardRect`（上、左、下、右）、背景的种类 `artboardBackgroundType`（1 白、2 黑、3 透明、4 自定，自定的颜色在 `Clr `）。
- 画板读成组，多记矩形、背景色和原始的块（有 `artd`、`abdd` 的也一起），存回 PSD 原样写回去。
- 合成：画板总按普通（隔离）的组合成；里面的东西先叠在一张底上，这张底在画板矩形里是背景色（透明的就是透明），矩形外是透明；叠完之后矩形外的部分去掉。
- 原生格式存原始的块（Base64），读的时候重新解析；ORA 没有画板，导出时当普通组，背景色不带。
- 图层列表里画板的行标"〔画板〕"。

### 3.17 混合模式补齐（F-051，0.3.1）

- 可分离的（逐个颜色分量算，b 是下面的颜色，s 是图层的颜色，都在 0..1）：
  - 颜色加深：b = 1 时 1；s = 0 时 0；否则 1 − min(1, (1 − b) / s)。颜色减淡：b = 0 时 0；s = 1 时 1；否则 min(1, b / (1 − s))（W3C）。
  - 线性加深：max(0, b + s − 1)。线性减淡（添加）：min(1, b + s)。
  - 强光：s ≤ 0.5 时正片叠底 (b, 2s)，否则滤色 (b, 2s − 1)（W3C）。柔光：用 W3C 的公式。
  - 亮光：s ≤ 0.5 时颜色加深 (b, 2s)，否则颜色减淡 (b, 2s − 1)。线性光：clamp(b + 2s − 1)。点光：s ≤ 0.5 时 min(b, 2s)，否则 max(b, 2s − 1)。实色混合：b + s ≥ 1 时 1，否则 0。
  - 排除：b + s − 2bs（W3C）。减去：max(0, b − s)。划分：s = 0 时（b = 0 为 0，否则 1），否则 min(1, b / s)。
- 不可分离的：色相、饱和度、颜色、明度照 W3C（亮度按 0.3、0.59、0.11 加权，超界时 ClipColor）；深色、浅色：整个像素取亮度（R + G + B）小的、大的那一个。
- 和普通的一样按 W3C 的源在上（source-over）合进去：结果 = (1 − αb)·s + αb·B(b, s)，再按 αs 叠。
- PSD 的混合键：idiv、lbrn、dkCl、div 、lddg、lgCl、sLit、hLit、vLit、lLit、pLit、hMix、smud、fsub、fdiv、hue 、sat 、colr、lum 。溶解（diss）不做，读入时改成正常并说明。ORA 规范里有的（W3C 那几种）照写，没有的（线性加深、亮光、线性光、点光、实色混合、减去、划分、深色、浅色）导出时写成正常。
- 拿用户文件里 PS 存的合并图像对照用到的几种；没有样本的照公式，实测结果里写明哪些没对照过。
- 混合模式的下拉表按 PS 的样子分组（组和组之间有分隔线）。

**2026-10-15 注（0.5，照参照软件量出来的改动）**：上面的公式是照 PS 公开的文字说明写的，从来没有和 PS 的结果对照过（本机没有 PS）。0.5 让参照软件打开我们写的文件再存一次，它存的合并图像就是它的合成结果，拿来对照，发现有五种模式在少数输入上和上面不一样。用户的 19 个 `.sai2` 和 2 个 PSD 里都没有用到这五种模式，改前改后和各自合并图像的对照结果逐个一样（`runs/sai2write/compare-after-modes.txt`），所以这只影响边角。参照软件是唯一量过的对照，下面就照它改（PSD、ORA、本程序的格式都一样用这一套）：

- 深色、浅色：比的是亮度（0.3、0.59、0.11 加权），不是 R + G + B。例：纯蓝加起来是 1，比 0.3 的灰（0.9）大，但亮度低得多，深色取纯蓝。亮度一样时取底色。
- 亮光：源是 0 时结果是 0（底是白的也是），源是 1 时是 1（底是黑的也是）。其余同上。
- 实色混合：b + s > 1 时 1，< 1 时 0；正好等于 1 时，源不超过 0.5 算 1，超过 0.5 算 0（白底配 0 是 1，黑底配 1 是 0）。相当于"亮光的结果和 0.5 比"：加深那一半用 ≥，减淡那一半用 >。
- 色相（以及共用 SetSat 的饱和度）：要改饱和度的那个颜色三个分量一样（灰的，没有色相）时，W3C 给 0，参照软件把红当成最大的分量，得到 (饱和度, 0, 0)，也就是色相按红算。所以色相模式下灰色的源给的是"底的饱和度、底的亮度、红的色相"；饱和度模式下灰色的底同理。

怎么量的：随机像素的 42 层测试文件里这五种模式的 296 个像素拟合候选公式（每种只有上面这一种全部对上，差最大 1）；再专门做一个边角文件 `edges`：色相、饱和度、颜色、明度、深色、浅色、亮光、实色混合各一个不透明的图层，14 种底色 × 14 种源色，都是 8 位里正好的值（灰、0、255、"加起来"和"亮度"比出来不一样的颜色、和正好是 1 的组合）。按上面的改动，两个文件的合并图像都 100%（差最大 1）。实色混合"正好等于 1"的规矩是在 `edges` 上第二、第三次才定下来的（先试了 ≥、再试了 >，各错 32 个像素）。

### 3.18 填充不透明度（F-065，0.3.1）

- PSD 的 `iOpa` 块是图层的"填充"（0..255），没有这个块就是 100%。另有 `tsly`（"透明形状图层"，没有就是开）。两个都读进来、存回去；原生格式里是 `fill_opacity` 和 `shapes`；ORA 没有，导出时填充乘进不透明度。
- 合成：普通的混合模式里，填充和不透明度一样，乘在图层的透明度上。PS 里有八种模式（颜色加深、线性加深、颜色减淡、线性减淡、亮光、线性光、实色混合、差值）的填充起作用的方式不同，公开的资料里没有确切的公式；按用户文件里 PS 存的合并图像校准（结果见"0.3.1 实测结果"），定下来的做法是：
  - 这几种模式各有一个"不起作用的颜色" N（拿它混合结果就是底色）：颜色加深、线性加深是白，颜色减淡、线性减淡、差值是黑，亮光、线性光是 50% 灰。实色混合没有，按普通的做法。
  - 填充 f 把图层的颜色往 N 拉：s' = N + (s − N)·f，透明度不变，再照常混合。
  - "透明形状图层"关着的：像素的透明度 α 也折进去，s' = N + (s − N)·f·α，按整块铺满（透明度 1，剪贴的乘上底的透明度）来混合。只在底下不透明时这样做，底下透明的地方按上一条。
- 面板：填充不是 100% 的图层，不透明度下面多一个"填充"滑块；改回 100% 以后滑块就不再显示。

### 3.19 单张图片：打开、导出、导入（F-143、F-147、F-148，0.4）

读：

- 按文件开头认格式（PNG 的 8 字节签名、JPEG 的 `FF D8 FF`），不看扩展名；两样都不是就说"不是 PNG 或 JPEG 图片"。
- PNG 用原有的 `png` 库，和 ORA 里读图层图像是同一段代码（8 位、16 位，灰度、灰度加透明度、RGB、RGBA、调色板、`tRNS`、隔行扫描）。`pHYs` 的单位是米时换算成打印分辨率。
- JPEG 用 `zune-jpeg`（MIT / Apache-2.0 / Zlib，纯 Rust）。输出一律要 RGB，灰度和 CMYK 的文件由它转换。EXIF 里的方向（1–8）照着转正（旋转、翻转都是整像素重排，不插值）。JFIF 的密度单位是英寸或厘米时当作打印分辨率。
- 两种都没有分辨率时按 72（PS 打开这种图片也是 72）。ICC 颜色配置、`gAMA` 不管，像素值照原样当 sRGB 用（本程序没有色彩管理）。
- 边长超过 16384（画布的上限）的图片不读，说明原因。先读文件头拿到尺寸再分配内存。

打开：画布和图片一样大，背景白色，一个图层"图层 1"，就是这张图。

写（导出，F-143）：

- PNG：和原来一样，合成图垫上背景色，8 位 RGB。"PNG（透明背景）"：合成时底下不垫背景色，从透明开始叠，得到预乘的 RGBA，换成非预乘的 8 位 RGBA 写出。两种都写 `pHYs`（打印分辨率）。
- JPEG：用 `jpeg-encoder`（MIT 或 Apache-2.0，其中正向 DCT 一段来自独立 JPEG 组（IJG）的代码，按 IJG 的条款要在随附文档里写明"本软件部分基于独立 JPEG 组的工作"，写在 README 里）。合成图垫上背景色，质量 92，色度不抽样（4:4:4：线稿的彩色边缘不发糊），写 JFIF 的英寸密度。
- 都先写临时文件再改名替换，和别的格式一样。

导入（F-148）：

- 图片读成一张分块表，左上角对齐画布中心减去半张图（宽高是奇数时向下取整），也就是放在画布中间。比画布大时自由变换的初始缩放取 min(画布宽 / 图宽, 画布高 / 图高)，等比缩到正好放得下；不大时是 1，不插值。
- 走自由变换（§3.8）那一套：变换的对象是这张图，进入变换时的样子就是上面这样；面板、手柄、三种方式、翻转、旋转 90° 都照常。和普通变换的区别只在落到哪里：
  - 导入为新图层：开始时在当前图层上面放一个新的空图层（位置规则和"新建图层"一样，当前是展开的文件夹时放进它里面），名字是文件名去掉扩展名。这个图层先不记撤销；预览时图片画在它里面。确定时把变换好的图放进去，再把"多了这个图层"记成一个撤销步骤；取消时直接拿掉它，当前图层回到原来那个。
  - 导入到当前图层：预览和确定时，图层的像素是"原来的像素上面盖一张变换好的图"（正常模式的覆盖，预乘：out = top + base·(1 − top.α)）。当前图层"保护不透明度"时，结果的透明度保持原来的，颜色取覆盖之后的颜色（按透明度换算回去）。确定时整层换掉，一个撤销步骤；取消时换回原来的像素。只在图片落到的分块上做覆盖，别的分块和原来共用。
  - 当前图层是文件夹、填充图层，或者锁定（含所在的组锁定）时，"导入到当前图层"不能用，提示原因。正在画蒙版时也不能用（图片是像素，不是蒙版）。
  - 选区：不限制导入的图，选区也不跟着动，导入结束后原样还在。
  - 没有改动（没拖过手柄）就确定，也照样导入（和普通变换"没变就不记一步"不同）。

### 3.20 保存与另存为（F-149，0.4）

- 文件对应的格式看扩展名：`.zhibi`、`.psd`、`.ora` 是分层的格式，"保存"能直接写；`.png`、`.jpg`、`.jpeg` 存不下图层，只能"导出"。
- 另存为：文件类型三种（纸笔画布、PSD、ORA）。按文件名的扩展名存；没写扩展名时系统对话框按选的类型补上。存完记下这个文件，之后"保存"直接写它。
- 保存：
  - 当前文件是 `.zhibi`，或是这次用"另存为"存过的文件：直接写。
  - 当前文件是打开进来的 PSD、ORA，还没在这次存过：先出"另存为"，文件名和类型默认是原文件。原文件里本程序不读的东西（PSD 的参考线、路径、额外的通道、颜色配置等；ORA 里不认识的元素）写回去时就没了，所以要用户在系统的"是否替换"里确认一次。确认过以后这个文件就算"这次存过的"。
  - 当前文件是打开进来的 PNG、JPEG：出"另存为"，默认纸笔画布，文件名同原来的。
  - 没有文件（新建的）：出"另存为"，默认纸笔画布。
- 导出（"导出…"）：PNG、PNG（透明背景）、JPEG、PSD、ORA，不改变当前文件，也不清"未保存"的标记。打开的 PNG 里有透明像素时默认选"PNG（透明背景）"。

| 55 | u8：位 0 剪贴；组上还有 0x40（展开着，不影响显示） |
| 56 起 | 参数，每个是 4 字节名字、u32 长度、内容，以 4 字节 0 结束。`name`：u16 字数加 UTF-16 的名字；`lmsk`：蒙版（见下） |

像素（`lpix`、`mpix`）：`dpcm`，然后每"条"一个 u32 长度，然后各条的数据，最后补齐到 4 字节；范围是 0 的空图层只有 4 个字节的 0。一条是 32 行高、和范围一样宽的一横条，从上往下。一条的数据是一串 32×32 的块，每块以两个字节的标记开头：第一个字节新文件里是 `FF`，有的旧文件（2021 年）里是别的固定值（见过 `8D`），读的时候不看；第二个字节高 4 位是类型，低 4 位是这一块的列号（从画布左边数，以 32 像素为单位）对 16 取余：

- 类型 0：接下来 u16 n，往后 n+1 块全透明；
- 类型 5：接下来每个通道一个 u16，整块一种颜色（像素是 B、G、R、A 四个，蒙版一个）；
- 类型 A：接下来 u16 长度 L，然后 L 字节的压缩数据；
- 类型 F：这一条结束。

像素值：每通道 16 位、预乘透明度，1.0 是 0x4000（读进来乘以 2 就是本程序的 15 位）。蒙版只有一个通道，值的意思看 `lmsk` 标志的第一个字节：是 1 时值是"挡住多少"（0x4000 完全挡住），范围以外完全显示；是 0 时值是"显示多少"，范围以外完全挡住（拿用户文件的合并图像核对出来的，见实测）。

压缩块：通道一个接一个（像素是 B、G、R、A 四个，蒙版一个），每个通道 1024 个数，按行从上往下。连成一条位流，每个字节从最低位读起，通道之间不对齐。每个数先预测，存的是"实际值 − 预测"：

- 第一行：左边那个（最左边的预测是 0）；第一列：上面那个；其余：左 + 上 − 左上，夹在 0 到 0x4000 之间。块外面当 0，各块互不相干。
- 差的写法：先数 0 有几个（z），读到 1 停；再读 1 位 f；n = 2z + 1 + f。n = 16 表示一串 0：再读 7 位 k，有 k + 8 个 0。否则读 n − 1 位 m（从低位起），|差| + 1 = 2^(n−1) + m；|差| 不是 0 时再读 1 位符号（1 是负）。

合并图像（`intg`）：`dpcm`，每个 256×256 的格子一个 u32 长度，然后数据；每一行格子后面另有两个字节的结束标记（不算在长度里）。一个格子：两字节的标记，然后逐行：这一行的 B、G、R、A 各一串（格子那么宽，画布右边、下边的格子按画布裁小），写法同上，每行结束补齐到字节。旧文件里没有 A（垫着白底）。值是 8 位、不预乘，预测同上但夹在 0 到 255。只用来核对。

参照软件把 8 位的 v 读成 floor(v × 16384 / 255)，预乘是 floor(颜色 × 透明度 / 16384)（拿 `blocks.png` 核对过，每个像素都对）。

`lmsk`（蒙版）：u32 蒙版的编号（`mpix` 用它）、i32 左、i32 上、u32 宽、u32 高（以 32 像素为单位），再 4 字节标志：第一个字节见上；第二个是启用（0 是停用）。单独的 `mask` 块（2 个旧文件里有）和同编号的 `mpix` 不属于哪个图层，看着是存下来的选区，不读。

混合模式：PS 有的 26 种各有一个编号（`norm` `dark` `mult` `cbrn` `lbrn` `drkc` `litn` `scrn` `cddg` `lddg` `litc` `over` `slit` `hlit` `vlit` `llit` `plit` `hmix` `diff` `excl` `fsub` `fdiv` `hue ` `sat ` `col ` `lum `，组的穿透是 `pass`），用 `modes.psd` 让参照软件转出来逐个核对过。另有五种是参照软件自己的，PS 里没有（公式拿用户文件的合并图像拟合，误差都在 1 以内；a 是这一层的透明度乘不透明度，b、s 是底色、源色，都是 0–1）：

| 编号 | 本程序的名字 | 底不透明时 |
|------|--------------|------------|
| `add ` | 提亮 | b + s·a |
| `sub ` | 压暗 | b − (1 − s)·a |
| `sbad` | 提亮/压暗 | b + (2s − 1)·a |
| `ddge` | 柔和减淡 | b ÷ (1 − s·a) |
| `burn` | 柔和加深 | 1 − (1 − b) ÷ (1 − (1 − s)·a) |

结果都夹在 0 到 1。底半透明时：颜色 = 源色·a·(1 − 底的透明度) + 上表的结果·底的透明度（推想的，没有对照过）。这五种不放进混合模式的下拉表；存成 PSD、ORA 时换成最接近的（线性减淡、线性加深、线性光、颜色减淡、颜色加深）。

读成本程序的文档：块表里的图层倒过来就是自下而上的顺序，深度照抄（组排在它里面的东西后面，和本程序一样）；像素放在 (32 × 左, 32 × 上)；伸出画布的照样留着（实现方案 §3.15）。`grid`、`symm` 跳过并在说明里交代。认不出的混合模式当正常处理并在说明里交代。文件里没有分辨率，按 72。文件头 0x24 处的编号是哪个图层，打开后当前图层就是它（找不到就是最上面的）。写见 §3.23。

### 3.22 剪贴组（0.4，读参照软件的文件时查出来的）

原来的做法：剪贴的图层各自直接叠在下面已经合好的画面上，透明度乘上底的透明度。用户的 `.sai2` 里底是"正片叠底"、上面剪贴着正常模式的图层时，和参照软件差得很远：参照软件（PS 默认的"将剪贴图层混合成组"也一样）是先把底和剪贴的图层单独合成，再按底的混合模式和不透明度叠下去。

现在的做法：

- 一个不剪贴、上面紧跟着剪贴图层的图层（底；穿透的组除外）开一块透明的底板。底在底板上按正常模式、不透明度 100%（蒙版、填充照常）画；剪贴在它上面的图层按各自的模式、不透明度，以 source-atop 叠在底板上（结果的透明度保持底的）；最后底板按底的混合模式和不透明度叠到下面。
- 剪贴的是穿透的组时，组里的东西也一层一层按 source-atop 叠在底板上。
- PS 的"透明形状图层"关着的那几种模式（§3.18）：在底板上，底有内容的地方都按"整块铺满"来混合。
- 向下合并剪贴的图层时同样按 source-atop 并进底里，合并前后看起来一样。

校准开关 `CLIP_MODEL`（0 原来的做法，1 只在底不是正常模式或不透明度不到 100% 时开底板，2 总是开），定为 2。

### 3.23 保存成参照软件的格式（F-146 的写入，0.5）

照 §3.21 反过来写。§3.21 里没弄清意思的几个数，照参照软件 2026 版自己存的样本填（样本里是什么就写什么，不猜意思），写出来的文件让参照软件实际打开来核对（见 0.5 的验收）。

整体：

- 块的顺序（块表和数据都是这个顺序）：`hist`、`intg`、各图层的 `layr`（从上往下）、各图层的像素（从上往下，每层先 `lpix` 后 `mpix`；组没有 `lpix`）。参照软件存的三个样本就是这样排的。不写缩略图 `thum`：参照软件 2026 版自己存的文件里也没有。
- 编号：图层自下而上从 2 起；蒙版接在最后一个图层后面，也是自下而上（样本里是这样）。
- 文件头：签名；标志 `0x01000000`；宽；高；0x1C 处 `0x1c599a`；块的个数；0x24 处当前图层的编号（用户的 19 个文件里这个数都是某个图层的编号）；16 字节 0；`80 80 80 FF`；`norm`。标志和 0x1C 的数照样本 `blocks.sai2`（参照软件 2026 版从 PNG 转存的）填，用户 2026 年存的文件 0x1C 也是这个数。
- `hist`：88 字节。UTF-16 的"年月日.时分秒.2"（保存时的协调世界时；最后的".2"照样本），补 0 到 64 字节；16 个随机字节；u64 的 1。样本里这三样是时间、看着像随机的 16 字节、小的计数，具体意思不知道。
- 像素块、合并图像里每块数据补齐到 4 字节（样本是这样）。

图层记录（§3.21 的表）：类型 `norm` 或 `fold`；8、12、20、24 写 0（参照软件从 PSD 转存的样本里都是 0）；范围、混合模式（组穿透是 `pass`）、不透明度（取整到 1%）、深度、保护不透明度、显示、剪贴（组展开着再加 0x40）照抄。参数：`name` 是 u16 字数加 UTF-16，后面补 0 到 4 字节的倍数（样本是这样），最多 255 个 UTF-16 单元，超出的截掉（参照软件的上限不知道，用户的文件里最长 17 个）；有蒙版的再写 `lmsk`；最后 4 字节 0。

像素（`lpix`）：

- 范围是有内容的地方，按 32 像素对齐（可以伸出画布，§3.15）。完全空的图层范围是 0，像素块只有 4 个字节的 0（用户的旧文件里见过）。
- 15 位换成文件的 16 位：(v + 1) ÷ 2 取整，颜色仍不超过透明度。
- 每条从范围的左边写到右边：全透明的块连成一段写类型 0（u16 是块数减 1）；整块一种颜色写类型 5；其余写类型 A；最后类型 F，它的列号是范围的右边。用户的文件里每条都是这样：行尾空着的也用类型 0 补到右边，没有透明的类型 5。
- 压缩块：预测同 §3.21；差为 0 的连着 8 个以上写成一串（一串最多 134 个，和样本里见到的一样），不足 8 个的逐个写。一个块最多 24 位 × 4096 个数 = 12 KB，放得进 u16 的长度。

蒙版（`lmsk` + `mpix`）：默认白的（范围外显示）写成标志第一个字节 1、值是"挡住多少"；默认黑的写成 0、值是"显示多少"（这两种用户的文件里都有）。第二个字节是启用，第三个字节 1、第四个 0（样本和用户的文件里都是这样）。范围是和范围外不一样的那些块；和范围外一样的块在两种写法里都是 0，写类型 0。整个蒙版都和范围外一样时写 (0, 0) 一块类型 0。

合并图像（`intg`）：拿要写进去的图层（见下）合成，底下不垫背景色，8 位、不预乘。每个 256×256 的格子：标记 `FF` + 格子的列号，然后逐行 B、G、R、A 各一串（预测同 §3.21，夹在 0 到 255），每行补齐到字节；每一行格子后面写 `FF` + 格子的列数（用户的文件里都是这样）。全透明的像素颜色写 0。

背景色：参照软件没有"背景色"，图层底下是它自己的纸（白的）。本程序的背景色是白的就不写；不是白的，最底下加一层"背景"（铺满画布、那个颜色），和存 PSD 时一样。读的时候不把它变回背景色（参照软件自己的文件里叫"背景"的图层不一定是这个意思）。

存不下的（参照软件没有这些）：

| 本程序有的 | 写成 |
|------------|------|
| 填充图层 | 纯色的画成铺满画布的像素，蒙版照样单独写；本程序画不出来的（渐变、图案）写成空图层 |
| 图层样式 | 不写 |
| 填充不透明度 | 乘进不透明度（存 ORA 时也这样） |
| 画板 | 当普通的组 |
| PS 的"透明形状图层"关着 | 不写这个设置 |
| 分辨率 | 文件里没有地方放（打开时按 72） |
| 锁定（不能改像素） | 不写 |

除了分辨率和锁定，有上面这些的，存完出一次说明（同读 PSD 时的说明，同一类只一句，后面列图层名）。同一个文件连着存，说明和上次一样就不再出。

保存的规矩同 §3.20：另存为、导出的文件类型加上它（排在 PSD 后面）；打开的 `.sai2` 第一次"保存"先出"另存为"，文件名和类型默认是原文件，存回原文件要在系统的"是否替换"里确认一次。先写临时文件再改名。

## 5. 文件格式

### 5.1 原生格式

要求：自己的、公开的、结构简单、别人写个脚本就能读。

- 一个 ZIP 容器，里面是：
  - `document.json`：画布尺寸、分辨率、背景、图层树（每层的名称、类型、可见性、不透明度、混合模式、锁定、偏移、对应的像素文件名）。
  - `layers/` 目录：每个图层一个 16 位 PNG，只包含该层有内容的外接矩形。
  - `merged.png`：合成后的整图，供其他程序和文件管理器预览。
  - `thumbnail.png`：缩略图。
- 版本号写在 `document.json` 里。读到不认识的字段时忽略；读到比自己新的版本号时拒绝打开并说明原因。（原先写的是"保留并原样写回"，开发时改掉了：要让未知字段跟着图层一起被排序、复制、删除，文档结构会为一个还不存在的需求变复杂。）
- 这个结构有意贴近 OpenRaster（同样是 ZIP 加一张清单加逐层 PNG），所以导出 ORA 几乎只是换一张清单。

### 5.2 交换格式

关于参照值的一条更正：测量时画面里的笔刷光标圆环有一部分压在墨迹上，这会让面积法少算一小段墨迹。少算的长度是固定的几个像素，所以笔速越慢、折合成的时间越长。规格里参照软件在 200 像素/秒下的跟随延迟（关稳定器 12.8 毫秒、默认档 23.3 毫秒）因此偏大，偏大多少没有量过；1000 像素/秒及以上受影响不超过约 3 毫秒。我们自己在 200 像素/秒下读到的 16.4 毫秒同样含有这个偏差。验收只用 1000 像素/秒的数值，结论不受影响。

与规格不一致、需要用户知道的地方：

- **没有做选项对话框**（F-160）。首版里没有需要放进对话框的设置：笔刷参数都在面板上，笔输入只有一种接口。等 Wintab 接口（P1）加进来时再做。
- **新建画布对话框是 4 项**（预设、宽、高、分辨率），没有名称和背景两项。背景目前固定为白色。
- **图层排序用"上移""下移"两个按钮**，不是拖动。
- **原生格式读到不认识的字段时忽略**，而不是保留并写回（§5.1 已改）。
- 没有状态栏。
- 鼠标作画仍固定按满压处理。

仍然存在的问题：

- 稳定器高档位的跟随延迟比参照软件大：档位 3 / 8 / 15 为 12.1 / 24.1 / 41.1 毫秒，参照为 15.9 / 21.2 / 29.5。平滑效果一致，滞后更多。原因见 §3.1 的模型缺口，还没有解决办法。
- 档位 15 的"抬笔后画完用时"是 9.8 毫秒，贴着 10 毫秒的线。
- 导出和保存对话框默认打开系统的"文档"文件夹；没有记住上次用的位置。
- 保存时要先把整张画布合成一遍来生成预览图，最大尺寸（16384×16384）下这一步约需 800 MB 内存。4000×3000、三层的画布实测保存 0.7 秒、打开 0.3 秒。
- 没有用真实的笔做过系统测试。M0 完成后用户试画过，反馈是"还行"。

开发中发现并修掉的问题：

- **图层混合的舍入误差**：非"正常"模式下向下合并时，几项各自四舍五入后相加，颜色可能比透明度多出 1，成为不合法的预乘像素，存盘再读回会差 1。这是写文件格式的助手在核对"逐像素一致"时发现的。已在混合函数里压回去，并加了覆盖 8 种模式的测试。
- **读入文件后新建图层可能重名**：编号现在会跳过已被用掉的名字。
- **一笔被拆成一个点加一条线**：笔在感应范围内时，系统会不时补发不带"来自笔"标记的鼠标移动消息，原先被当成鼠标处理，把正在画的一笔打断了。M0 里就有这个毛病，只是自动测试的笔画中间没有停顿，没暴露出来。现在笔在感应范围内时一律不理会这类鼠标消息。
- **测量工具的面积法又修了一次**：改成"总面积 ÷ 总长度"之后，起笔渐细较长的笔画（稳定器高档位）延迟被高估约 10 毫秒。现在用线的中段各列墨量的平均值，对旋转和渐细两种情况都不偏。上表里的数字是修正后重测的。

M2 做了什么：

- **选区**：矩形选框、套索、魔棒三个工具，按住 Shift 加选、Alt 减选；"选择"菜单里有全选、取消、反选、扩大和收缩 1 像素、显示或隐藏边线。有选区时，画、擦、清除、填充都只作用在选区里。
- **油漆桶**：颜色容差、缝隙闭合（0 到 10 像素，出厂是关）、看哪里的颜色（所有图层合起来，或者只看当前图层）。做法见 §3.5。
- **移动和自由变换**：移动工具，或者用别的工具时按住 Ctrl 拖动；有选区时只动选中的部分，选区跟着走。Ctrl+T 进入自由变换：拖角缩放（默认等比，按住 Shift 可以变形），拖边只拉一个方向，框内拖动是移动，框外拖动是旋转（Shift 每档 15°）；面板上有确定、取消、翻转、转 90°、复位。拖动中用快速采样，确定时用高质量采样重算一遍；像素每次都从进入变换时的原图算起，来回拖不会越拖越糊。不缩放、角度是 90° 整数倍时，结果是原像素的原样搬运，不经过插值。
- **图层**：保护不透明度、锁定、剪贴三个开关；合并可见图层、拼合成一层；填充前景色；白底变透明（把扫描的白底线稿变成透明底，处理后叠在白底上看起来不变）。当前图层锁定或者隐藏时不开始一笔，光标的圆环里多一道斜杠。
- **PSD 和 ORA**：打开、导出。打开时有没能照原样读进来的内容，会列出来告诉用户。打开这两种文件后按"保存"，会另起一个我们自己格式的文件名，不去覆盖原文件。
- **快捷键自定义**：一个列表对话框，点功能、按键，就改了；这个键原来绑着别的功能的话，那一个被解除。键位存在设置文件里，只写改过的。菜单上的快捷键提示跟着变。
- **按住工具键借用**：按住某个工具的键，画一笔，松开，回到原来的工具；只按一下不画，就是换工具。
- **颜色面板**：红绿蓝滑块、色相饱和度明度滑块、色板，出厂不显示。面板可以整组换到右边。
- **Wintab 笔输入**和**最小压力**：在"笔"菜单里切换，不用重启。出厂仍然用 Windows 的笔输入。
- **马克笔**（用户 2026-10-14 要求加的，F-031，做法见 §3.6）：叠涂不会越叠越深，不透明度只升到这一笔的浓度为止，颜色向新色过渡。第一版做成了"叠涂变深"，用户拿参照软件对比后当天改成现在这样。原来的"铅笔"按用户的意见改名为"笔"，起草和勾线都用它；设置文件里沿用原来的名字，调好的参数不丢。工具栏上面一行现在是笔、马克笔、喷枪、橡皮、油漆桶。马克笔的快捷键是 N。
- **笔当橡皮用**（用户试用后加的）：笔倒过来用橡皮那头，或者用笔身上的按键在驱动里把笔切成橡皮时，自动换成橡皮工具；切回笔尖时换回原来的工具。只在两笔之间换。Windows 笔输入看笔的"倒置""橡皮"两个标志位，Wintab 看驱动登记的光标类型（这块板子的驱动把 1 号登记为笔、2 号登记为橡皮）和"倒置"状态位。
- 大面积重画（平移、缩放、变换预览）和变换的重采样分给几个线程做；一笔带来的小块重画不变，仍在当前线程上立刻做完。

与规格不一致、需要用户知道的地方：

- **图层文件夹（F-055）没有做。** 它要动图层的数据结构、合成、撤销、图层面板和三种文件格式，移动和合并时的规则也有不少要拿主意的地方（一个图层上移时什么时候算"进了文件夹"、文件夹整体怎么移动）。这些更适合在用户实际用过一阵之后再定，所以从 M2 里拿了出来。PSD 和 ORA 里的图层组读入时展开成普通图层，并给出提示。
- **锁定只有两个开关**（保护不透明度、锁定），规格里写的是 4 个。
- **自由变换只有一种方式**：缩放、旋转、移动合在同一组手柄上。没有"扭曲"（四个角各自拖动的那种变形）。
- **没有做选项对话框（F-160）**：现有的设置都放在"笔"和"视图"两个菜单里，没有需要对话框的。
- **按住工具键借用的判定**是"按着的时候有没有用过"，不是规格里写的"按住超过 250 毫秒"。这样慢慢按一下不会被误当成借用。
- **选区的边线是不动的黑白虚线**，不是流动的那种。
- **选区的扩大和收缩一次固定 1 像素**，没有输入数值的地方。
- **移到画布外面的内容会被裁掉**：图层只保存画布范围内的像素。一次拖动或一次变换之内来回移动不会丢东西，确认之后出了画布的部分就没有了。
- **回车、Esc 和单按的数字键是固定的**，方向键也不能绑。
- 交换格式里保不住的东西：两种格式都是每通道 8 位；ORA 不保存剪贴和两个锁；PSD 保存剪贴和保护不透明度，不保存锁定；撤销历史、选区、当前图层都不保存。
- 读 PSD 时：图层组展开；蒙版、矢量蒙版、图层样式忽略；文字图层和智能对象只留像素；调整图层跳过；本程序没有的混合模式改成"正常"；用 ZIP 压缩像素的图层读不了（一个图层都读不出来时，读入合并后的图像）；CMYK、Lab、索引色、灰度的文件打不开，会说明是哪种模式。每一项都会列在打开后的提示里。
- JPEG 的读写（§5.2，P1）还没做。

仍然存在的问题：

- Wintab 的位置、中文输入法下的快捷键对话框、"笔当橡皮用"三项，修好后用户 2026-10-14 复测都没问题。Wintab 仍是可选项，出厂不启用。
- **改过之后的马克笔还没有用真笔画过。** 单元测试覆盖了它的规则（交叉处不变深、不透明度只升不降、换色时向新色过渡、颜色合法）。
- **这一轮的界面检查走的都是鼠标消息**，不是笔。笔输入的代码这一轮改过（为了让 Wintab 和 Windows 笔消息走同一条路），逻辑上与之前等价。用笔实际走过的只有三样：延迟回归、按住 Ctrl 拖动、选框的加选和减选。油漆桶、魔棒、套索、变换的手柄没有用笔点过，用的是鼠标消息。
- **"打开"和"导出"两个菜单命令没有在实际窗口里点过**（它们要经过系统的文件对话框，后台测不了）。PSD 的打开是用命令行参数验证的；导出只验证了写文件的函数（单元测试和与 GIMP 的互通）。没验证的是对话框这一段：在导出对话框里选了"Photoshop 文件"却没写扩展名时，系统补上的扩展名对不对；以及打开 PSD 后按"保存"是不是另起文件名。
- 铺满整张画布的图层做自由变换时，预览约每秒 26 次，能用但不算顺。
- 变换预览用的是快速采样，缩小时很细的线可能时有时无，确认后才是最终质量。
- 带软边的选区（魔棒选出来的）移动之后，原来的位置上会留下一圈很淡的痕迹。
- 整张 3000×2000 的选区扩大或收缩一次要约 0.35 秒；400×300 的选区感觉不到停顿。
- 油漆桶每次要按整张画布分配工作内存（每像素 2 到 3 个字节，没用到的部分不占物理内存）：最大画布上是 512 到 770 MB。3000×2000 的画布上点一下，单元测试里计时是 22 到 68 毫秒（缝隙闭合开得越大越慢）。
- M1 留下的问题没有变化：稳定器高档位的滞后、保存大画布时的内存、文件对话框不记位置。

开发中发现并修掉的问题：

- **变换预览太慢**：第一版在铺满的图层上每步 50 到 76 毫秒。原因是每一步都要把整层重采样、整张画布重新合成并重画，全在一个线程上。把重画和重采样按行、按分块分给几个线程之后是上表里的数字。
- **测试改了用户的设置**：头一批后台测试用的是用户自己的设置目录，把铅笔的快捷键改成了 Q、打开了颜色面板、稳定器调成了 0。发现后已经改回测试前的样子；之后的测试实例都用单独的设置目录。
- **对话框里的说明文字各自带一块灰底**：改成跟对话框一样的白底。
- **打开 PSD 后的提示**原先用系统的消息框，后台截图里只看到第一行字，后面的说明是空白（没有查清是真没画出来还是截图取不到）。换成了自己的说明窗口：带滚动条，文字可以选中复制，条目再多也不会把窗口撑大。换了之后三条说明都显示完整。
- **Wintab 下线画在上下颠倒的位置**（用户实测发现）：程序原先拿头几个数据包和系统光标的位置比对来猜纵轴方向，笔刚进感应范围时光标往往还停在别处（比如刚点过的菜单上），就猜反了，而且一猜定终身。改成照 Wintab 规范固定倒转纵轴（规范里数位板的原点在左下角），不再猜。
- **中文输入法开着时，快捷键对话框里绑不上字母键**（用户实测发现）：输入法先把按键截走了。主窗口在 M1 就关掉了输入法，这个对话框是另一个窗口，漏了。现在对话框和它里面的控件都不用输入法。用户已复测。
- **大笔刷严重卡顿**（用户实测发现：笔刷开到最大时马克笔几乎没法用，笔也卡）。原因在笔画引擎：样本之间的曲线被切成每段 2.5 像素的小段，每一小段都按一个完整的胶囊去算覆盖率，500 像素的笔每来一个样本就要把一个直径 500 的圆重算好几遍。笔每 5 毫秒送来一个样本，处理不过来就越积越多。改了三处：曲线小段的长度随笔刷半径放大（不小于半径的一半）；每一行只走胶囊实际覆盖的那一段像素，已经涂到这一段最大浓度的像素直接跳过；大面积时按分块分给几个线程。另外把显示重画分线程的门槛从 40 万像素降到 15 万。新增一个平时不跑的计时测试（`big_brush_timing`），视图 100%、3000×2000 画布上，每来一个样本的耗时：

  | 情形 | 改前：引擎 / 重画 | 改后：引擎 / 重画 |
  |------|------------------|------------------|
  | 笔，大小 500，每样本 5 像素 | 4.25 / 2.69 毫秒 | 0.87 / 2.18 毫秒 |
  | 马克笔，大小 500，每样本 5 像素 | 6.25 / 2.85 毫秒 | 0.96 / 2.22 毫秒 |
  | 马克笔，大小 500，每样本 20 像素（快速划过） | 15.08 / 2.26 毫秒 | 0.99 / 1.85 毫秒 |
  | 同上，视图缩到 56% | — | 1.01 / 2.63 毫秒 |
  | 笔，大小 10 | 0.01 / 0.07 毫秒 | 0.01 / 0.06 毫秒 |

  抬笔时把一整笔并入图层，大小 500 的一笔要 8 到 17 毫秒（改前 19 到 56 毫秒）。这些是核心模块的计时，没有在实际窗口里用笔复测。
- **马克笔边缘太糊**（用户实测发现，笔刷开得很大时）：软边宽度原先与"1 − 硬度"成正比，500 像素的笔在硬度 90% 时边缘糊出约 26 像素。改成与它的平方成正比（90% 时约 3.5 像素），马克笔出厂硬度改为 100%。边缘软硬仍在"边缘硬度"滑块上调，马克笔面板上加了一行提示。
- **PSD 里"隐藏"标志位的含义**：写这个模块时拿 GIMP 对照发现，规格书上对这一位的叫法和 GIMP 读写文件时的实际用法对不上，照字面实现的话图层的显隐会全反。按 GIMP 的实际用法做了，两个方向都验证过。

### 0.2：图像编辑

内容（用户 2026-10-14 定的范围）：自由变换补上扭曲、斜切、网格（F-080，§3.7、§3.8）；液化（F-083，§3.9）；调色与模糊（F-095，§3.10）。

验收：

| 指标 | 合格线 |
|------|--------|
| 不弹对话框 | 扭曲、网格、液化、三种滤镜，进入、拖动、确定全程不出现对话框 |
| 撤销 | 每一种确定后都是一个撤销步骤，撤销一次回到之前，未保存标记跟着变 |

0.2 做了什么：

- **自由变换**：面板上多了"自由""扭曲""网格"三个方式按钮。扭曲：拖角只动这个角（透视），拖边斜切；自由方式下按住 Ctrl 也是这样。网格：4×4 个点，拖一个点，画面平滑地弯过去。三种可以叠着用，移动、缩放、旋转时扭曲和弯曲跟着走。读数下面注明"另有扭曲"或"另有网格变形"。只做过斜切的，确定时仍走仿射那条路。
- **液化**：工具栏第十个工具（出厂键 R），六种方式：推、顺时针转、逆时针转、收缩、膨胀、复原；大小、强度两个滑块，压力管强度；大小也跟着方括号键走。第一笔开始一次液化，按回车或者"确定"、换工具、做别的操作时落实，Esc 或"取消"放弃。液化里撤销、重做的是液化里的一笔。方式、大小、强度存进设置文件。
- **滤镜**：新加"滤镜"菜单（色相/饱和度、亮度/对比度、模糊），色相/饱和度出厂键 Ctrl+U。打开后面板换成滑块和确定、取消、复位，画布跟着滑块变；回车确定，Esc 取消；滤镜打开时画布上只能看不能画。
- 关窗口时，进行中的变换、液化、滤镜先确定下来，"要不要保存"问得对（原来关窗口时进行中的自由变换会被直接丢掉，也没有提示）。

与规格不一致、需要用户知道的地方：

- **液化的"推"从内容外面推进去时，内容被推在笔刷前面、挤在一起变细**，而不是被笔刷中心带着走（从内容上起笔才是带着走）。这是"每个像素按权重跟着笔移动"这个做法本身的结果，单元测试里写明了这种行为。
- **网格固定是 4×4 个点**，没有调疏密的地方。拖一个靠边的点时，边上的点不动，画面从边上斜着离开，弯得比较急（插值曲面在边上按直线外推）。
- 滤镜的数值没有输入框，只能拖滑块；模糊半径在滑块上按平方根铺开（小半径那头分得细），色相取整到 1°，其余取整到 1。
- 模糊用的是"扩展方框"（§3.10），比规格原来写的多了一点：小半径时也连续可调。

仍然存在的问题：

- **500 像素的液化笔每个样本约 4.5 毫秒**（窗口里），贴着笔样本间隔 5 毫秒。跟不上时系统会把几个样本攒在一条消息里，我们一批只重算、重画一次，所以不会越积越多，但比同样大小的笔（3.3 毫秒）重。剩下的大头是每个样本三次"开 8 个线程再收回来"（每次约 0.35 毫秒）和预览要重采样的约 26 万个像素；一个常驻的线程池能同时让笔和液化都快一些，没有做。
- 铺满的大图层上扭曲、网格的预览约每秒 21–24 次，滤镜约每秒 24 次，能用但不算顺。
- 自由变换的扭曲没有用 Ctrl 实际按过（后台驱动按不下修饰键），用的是面板上的"扭曲"按钮；两条路在代码里是同一个判断。
- 没有用真笔试过液化的压力，也没有在英文界面下打开过这些面板（英文字的宽度有单元测试）。
- 后台测试时发现：松开鼠标后笔刷圆环跳到测试机上真实指针所在的位置。这是系统在放开鼠标捕获时补发了一个真实位置的移动消息，不是程序的问题，实际用的时候圆环本来就在真实指针下面。

开发中发现并修掉的问题：

- **液化里按住 Ctrl 拖动（临时移动）会被液化盖掉**（自查代码时发现）：移动从液化的预览像素开始，之后确定液化时又把图层换回液化前的原图再算一遍，移动就丢了。现在按住 Ctrl 拖动之前先把液化确定下来。
- **液化第一版每个样本 5.1 毫秒**（窗口里，铺满的图层）。改了三处：外接方框四个角上碰不到圆的分块不再复制和计算；被撤销快照共用的分块在各自的线程里复制，不再在开线程之前一块一块地复制；预览只重算这一下真的改过的分块。改后 4.5 毫秒。

### 0.3：文件夹、蒙版、填充图层、图层样式（2026-10-15）

内容：图层文件夹（F-055，§3.11）、图层蒙版（F-058，§3.12）、填充图层（F-061，§3.13），图层列表里拖动排序（F-050）。用户试用后加上（2026-10-15）：图层样式的保留和三种效果的显示（F-062，§3.14），画布外的内容不裁掉（F-063，§3.15）。

文件格式：

- 原生格式 `document.json` 升到版本 2：每个图层多 `depth`（深度，0 是最外层），文件夹有 `"kind": "folder"`、`pass_through`、`open`，填充图层有 `"kind": "fill"` 和 `fill`（纯色是 `{"type": "solid", "color": "#RRGGBB"}`，渐变和图案是 `{"type": "other"}` 加上它存着的像素；从 PSD 读来的都另带原始描述符，Base64），有蒙版的有 `mask`（PNG 文件名、位置、默认值、是否停用）。列表仍是自下而上、平的，和图层在程序里的样子一样；版本 1 的文件照常读（全部深度 0）。

- ORA：文件夹写成嵌套的 `stack`（穿透写 `isolation="auto"`，普通文件夹写 `isolate`），读入时嵌套的 `stack` 是文件夹。ORA 规范里没有蒙版和填充图层：导出时把蒙版乘进像素、填充图层画成像素。

窗口里做过的：打开带组、蒙版、填充图层的 .zhibi；点三角展开折叠的组；点眼睛隐藏、显示；点"蒙"那一格后用笔在蒙版上画，画到的地方隐藏，撤销复原；把图层拖出组、拖进组的中间（拖着的时候组那一行有蓝框），撤销；选中组用移动工具拖，组里带渐变蒙版的图层连同蒙版一起走，撤销；200 层的文档里把列表往下滚，再点眼睛两下，列表停在原处。

0.3 做了什么：

- **组**（规格里叫图层文件夹，界面上叫"组"，和 PS 一样）：可以套好几层，能折叠；"穿透"和普通两种（新建的是穿透）。新建组、放进新组（Ctrl+G）、上移下移进出组、拖动排序、删除和复制连里面的一起、向下合并把整个组合成一层、移动和自由变换整个组。
- **蒙版**：每个图层、填充图层、组都可以有一个。图层面板上"加蒙版"（有选区时只显示选区里）、"删蒙版"、"停用蒙版"；"图层"菜单里还有"应用蒙版"。图层行右边"蒙"那一格点了就在蒙版上画。移动、变换时蒙版跟着走。
- **填充图层**：纯色的现算；渐变、图案显示文件里存着的像素。面板上"用前景色"、"栅格化"。
- **文件**：PSD、ORA、.zhibi 都保留组、蒙版、填充图层（ORA 没有蒙版和填充图层，导出时画进像素）。
- 图层列表能用滚轮滚动，行按深度缩进，组的行后面有"〔组〕"，填充图层有"〔填充〕"。

与规格不一致、需要用户知道的地方：

- **渐变、图案填充图层不自己画**（§3.13，2026-10-15 改）：显示 PS 存在文件里的像素，存回 PSD 原样不变。
- **删除蒙版、停用蒙版不在菜单里**：菜单项已经 60 个，这两项只在图层面板上，也可以在快捷键里绑键。
- **GIMP 存的 ORA 里的穿透组读进来是普通组**：GIMP 写 ORA 时不写 `isolation`，规范里没写就是隔离的。
- 蒙版那一格只显示一个"蒙"字（英文 M），不是缩略图。

仍然存在的问题：

- **拖动排序时列表不会自己滚**：图层多、要拖到看不见的地方时，拖着的同时转滚轮；或者用上移、下移。
- 液化、滤镜只改像素，不改蒙版；液化有蒙版的图层时蒙版不跟着变。
- **图层样式的画法是拿一个文件校准的**：发光在这个文件的参数（范围 50%、扩展 0 和 3%、阻塞 15%、大小 21 到 95 再乘 200%）附近和 PS 很接近，别的参数（尤其是范围离 50% 远的、大扩展的）没有对照过；投影没有能对照的数据。等高线、杂色、"精确"手法只是近似，读入时会说明。
- 画带样式的图层时，效果在落笔之后才跟着变；大图层上算一次要几十毫秒（用户文件里最重的那个是 81 毫秒），落笔时会顿一下。移动、变换带样式的图层时，每拖一下都要重算效果。
- 用户第二个文件右上角还有约 0.3% 的像素和 PS 差 10 以上，不画样式时就有，原因没查。
- 向下合并时带样式的图层合成一张图（和 PS 一样），"滤色"之类的效果叠在透明处合并后看起来会变（PS 也是这样）。
- 组的混合模式选"穿透"在弹出菜单里，后台驱动选不了弹出菜单，这一项没在窗口里点过（代码和其他混合模式同一条路）；Ctrl+G 也没按过（修饰键按不下），走的是菜单命令。
- 英文界面下没有打开过图层面板（英文字的宽度有单元测试）。

开发中发现并修掉的问题：

- 用户试用时发现：点眼睛显示一个隐藏的组或图层，列表会跳到别处。原因是每次改动之后列表都滚到当前图层；改成只在当前图层换了、图层多了或少了时才滚。
- ORA 里没写 `isolation` 的组，起初读成了穿透；规范的默认值是隔离，改了。
- 代码复查找出的几处：变换、液化、滤镜进行中拖动当前图层那一行，挪完之后会把像素写进别的图层（现在拖动松手前先把它们确定下来）；没有选区时把蒙版填成灰色，默认值成了灰的，移动或存盘后变回全白（现在灰色写进画布上的分块，默认值只有全黑、全白两种）；渐变填充图层存成 PSD 再读，存着的像素丢了（读的时候填充图层的像素不再因为"与画面无关"的标记而跳过）；撤销"加蒙版"之后编辑对象还停在蒙版上，图层画不上（撤销、重做之后重新判断）；组锁定时清除、填充、加蒙版、整体移动还能改到组里的图层（现在组锁定就是里面都锁定）；滚轮往下滚过头后往回滚要先空转几下；列表滚动着时拖到下面空白处，图层会被放到整个文档的最底下（现在当作落在最后一行的下沿）；纯色填充图层存成 PSD 时没有像素，不认识填充图层的程序看到的是空图层（现在写上铺满画布的像素，GIMP 打开逐像素一致）。
- 有组时画笔比平放慢约一半：这一块里没有内容的组也要整块拷贝、过渡一遍。现在跳过，差距降到约 15%。
- 用户用另一个 PSD 试时，提示里有"超出画布的部分已裁掉"和"图层样式被忽略了"。加了 F-063（伸出画布的内容照 PS 的样子留着）和 F-062（样式保留，投影、外发光、内发光画出来，按 PS 存的合并图像校准），见上表。
- 用户试用时问"滤镜怎么用、画笔圈里的斜杠是什么"：当前选中的是组，滤镜什么反应都没有。用户定的是用法不变（滤镜仍只对普通图层），加提示：当前图层画不了或者滤镜用不了时，左列工具下面用暗橙色写明原因（组、填充图层、正在画蒙版、隐藏、锁定，各有说法，最多三行），"滤镜"菜单里用不了的项变灰，"添加蒙版""应用蒙版"用不了时也变灰。窗口里看过填充图层、组两种提示，换到普通图层后提示和斜杠一起消失；菜单变灰是弹出菜单，后台驱动截不到，没在窗口里看过。

参照软件的格式（F-146，§3.21）：

格式是怎么弄清的：先只看用户文件的字节（不加密：开头是签名，块表、图层记录都是明文），容器部分和第三方公开的说明一致；压缩块的写法、预测、蒙版、混合模式是用参照软件自己转出来的三个样本（内容是我们生成的已知图案，用户同意后在用户不用电脑时由我操作参照软件转存）一位一位核对出来的。核对的手段是参照软件存在每个文件里的合并图像：我们读进来自己合成，和它比，只出数字，不看画面。

| 文件 | 尺寸 | 图层 | 和文件里合并图像的差 |
|------|------|------|----------------------|
| 三个样本 | 256×96 至 256×256 | 1–33 | 每个像素 ≤ 1；`blocks` 和原 PNG 逐像素一致，`layers`、`modes` 的每个属性和原 PSD 一致，26 种混合模式的编号逐个对上 |
| 用户的 19 个文件（2021–2026 年存的） | 886×1920 至 9449×11811 | 2–158 | 全部差 ≤ 2 的像素 100.00%（四舍五入到两位）；差最大的一个文件里最大差 14，其余最大差 1 |

读入时间（release，本机）：小文件几十到几百毫秒；6000×8000、158 层的 18 秒；9449×11811 的 35 秒。

一路上找出的问题（按发现的顺序），每条都靠合并图像的数字定下来：

| 现象 | 原因 | 改法 | 改后 |
|------|------|------|------|
| 2021 年的四个文件读不进来 | 块标记的第一个字节不是 FF（是 8D） | 不看这个字节 | 读进来了 |
| 一个文件里有个图层没有 `dpcm` | 范围是 0 的空图层只有 4 个字节 | 范围是 0 就不读像素 | 读进来了 |
| 旧文件的合并图像解不开 | 旧版本只有 B、G、R 三个通道，每行格子后面还有两字节的结束标记 | 两种都认 | 能对照了 |
| 底是"正片叠底"、上面剪贴着正常图层的地方差得很远（两个文件 89%） | 剪贴组的合成方法不对 | §3.22 | 100% |
| 用了参照软件特有模式的五个文件只有 58%–80% | 那五种模式不是 PS 的模式 | 新加五种模式，公式拟合出来 | 100% |
| 一个文件 5% | 图层记录里那两个"偏移"不该用；12 个蒙版的标志第一个字节是 0，值的意思反过来；剪贴在组上的穿透的组要一层层按 source-atop 叠在底上 | 不用偏移；按标志读蒙版；§3.22 | 100%（最大差 14） |
| 一个 6000×8000 的文件 99.41% | 标志是 0 的蒙版范围以外是挡住的 | 照这个读 | 100% |

剪贴组改了以后（§3.22）重新量了用户的两个 PSD：第一个不变（99.67%，剩下的差在外发光附近，同 0.3.1）；第三个从 99.50% 变成 100.00%（差 >10 的从 0.14% 变成 0）。原来以为是填充不透明度的推想做法不准，其实是剪贴组的合成顺序。

没解决、没测的：

- 记录里那两个像"偏移"的数到底是什么不知道，不用它的结果是对的。
- 参照软件特有的五种模式在底半透明处的做法是推想的；`grid`、`symm` 一类的辅助图层（尺子）不读；文字、形状、线稿图层用户的文件里没有，没见过它们的格式。
- 不能写成这种格式（用户说暂时不做）。

## 7. 风险

| 风险 | 影响 | 应对 |
|------|------|------|
| 所选界面框架拿不到完整的笔数据（压力、亚像素坐标、历史样本） | M0 就卡住 | 笔输入不经过框架，直接向系统取；研究阶段写的记录器已经验证过这条路 |
| 延迟达不到合格线 | M0 验收不过 | 合格线取的是对照软件的水平，余量大；最简程序实测约 3 毫秒，说明系统本身不是瓶颈 |
| 处理器渲染在旋转视图、大笔刷、高分辨率屏上不够快 | 导航卡顿 | 只重采样脏区域；拖动中用快速采样、停下后补高质量采样；实在不够再考虑图形处理器，但不预先为它设计 |
| Wintab 驱动之间的差异 | 部分数位板没有压感 | 首版只做 Windows 指针输入；Wintab 放 P1，并保留接口选择开关 |
| 第三方库的许可证与 GPL-3.0 不兼容 | 不能发布 | 引入任何依赖前核对许可证；带"非商业"条款的库一律不用 |
| 混色效果没有实测目标 | 做出来不好用 | 放在 P1，先发一个不含混色的可用版本 |
| 所有测量都来自合成输入，没有真实的笔和主观评分 | 指标都达到了但手感不对 | 文档里已写明；M0 做出来后请用户实际画几笔，这比任何指标都直接 |
| 范围蔓延 | 做不完 | 功能列表里已标出"不做"；新增功能必须先进功能列表 |
| 净室纪律 | 法律风险 | 开发阶段只读 `docs/spec/`；`analysis/` 不入库、不进入开发环境的上下文 |

## 8. 需要用户决定的点

1. 技术选型（§1.4）：我建议方案二（Rust 加 Windows 原生接口、界面自绘），代价是只支持 Windows。
2. 像素格式用 15 位定点（质量好、内存翻倍）还是 8 位（简单、省内存）。我建议前者。
3. 原生格式用"ZIP 加 JSON 加逐层 PNG"是否可以接受。
4. 验收合格线取"不差于 GIMP 和画图"是否可以接受。
