## 2. 实际改动

### 小笔段只访问本次触及的分块

文件：[src/core/src/stroke.rs](../../src/core/src/stroke.rs)。

原先每个笔段都调用 `MaskMap::many_mut`。该函数为需要的坐标建立集合，再扫描这整笔已经积累的分块表。即使只画一个很小的局部笔段，也会检查大量无关的历史分块；同时，每段都会查询系统可用线程数。

现在，小于现有并行门槛的笔段直接逐一访问本次触及的分块，完成后返回。达到门槛的大笔段保留原来的并行路径。覆盖率、压力、曲线、颜色混合和稳定器算法未改动。

新增默认忽略的 `long_stroke_timing`，用于测量不同历史分块数量下的小笔刷计算成本。

### 跳过灰底采样，并均分实际需要采样的行

文件：[src/core/src/view.rs](../../src/core/src/view.rs)。

原先缩小画布后，画布外的灰色背景也逐像素执行多重采样，每个屏幕像素最多采样 16 次。重绘线程按整个待画矩形的行数划分，部分线程只负责灰底，采样工作集中在其他线程。

现在先计算画布在屏幕上的外接矩形，并保留原有抗锯齿余量：

- 外接矩形以外直接填灰底。
- 上下纯灰底行先填好，只把实际有采样工作的行分给工作线程。
- 矩形内仍使用原来的采样点、颜色平均方法和相对坐标，保持原来的浮点舍入。

新增 `viewport_timing` 和边缘采样一致性测试，并扩展整块重绘与分条重绘的一致性测试，覆盖缩放、旋转、翻转、局部重绘、非零视口偏移及画布完全移出视口的情况。

### 构建配置试验

试验过 `lto = "thin"` 与 `codegen-units = 1` 的组合，各项任务的收益不一致，因此没有写入项目配置。release 的 `debug = 1` 保留，未添加依赖。性能检查阶段的版本号为 `0.5.1`；随后用户要求发布本次改动，按项目版本规则将版本号更新为 `0.5.2`。对外发布包沿用项目流程，单独关闭调试信息并重映射本机源码路径，不改变默认 release 配置。

## 3. 性能结果

### 全视口重绘

条件：3000×2000 的合成画布、1920×1080 视口、显示缓存已预热。每种视图重绘 21 次取中位数，旧版与最终版交替运行三轮，再取三轮中位数。五种视图前后的像素校验和全部相同。

| 视图 | 优化前 | 优化后 | 变化 |
|---|---:|---:|---|
| 100%，不旋转 | 1.888 ms | 1.821 ms | 耗时减少约 4% |
| 50%，不旋转 | 4.739 ms | 3.968 ms | 耗时减少约 16% |
| 25%，不旋转 | 12.590 ms | 4.230 ms | 耗时减少约 66%，约快 3 倍 |
| 100%，旋转 0.4 弧度 | 4.802 ms | 4.944 ms | 耗时增加约 3% |
| 50%，旋转 0.4 弧度 | 5.227 ms | 5.270 ms | 基本不变 |

最终数据来源：`runs/perf-20261015/final-*-viewport.txt`。早期试跑的机器负载、代码阶段与最终测试不同，不能把早期日志与最终日志混在一起计算提升比例。

### 长笔画的小笔刷计算

条件：笔刷大小 10，预置本次不触碰的历史覆盖率分块，再输入 4000 个局部样本。下表为三轮“每样本平均耗时”的中位数，仅计笔画引擎。

| 历史分块数量 | 优化前 | 优化后 |
|---|---:|---:|
| 0 | 2.885 μs | 1.559 μs |
| 512 | 7.282 μs | 1.446 μs |
| 4096 | 36.317 μs | 1.456 μs |

在 4096 个历史分块的测试中，该局部计算约快 25 倍；优化后不再出现原来随历史分块数增加而明显变慢的情况。数据来源：`runs/perf-20261015/round-*-long_stroke_timing.txt`。

### 测量边界

- 大小 500 的笔刷，每样本引擎加重绘仍约 3–4 ms，没有明显改善。
- 旋转视图没有获得明确收益，100% 旋转用例在本次测量中略慢。
- 这些是本机 release 构建的核心计算测试，不包含 Windows 消息处理、GDI 呈现、数位板硬件或显示器延迟。
- 重绘测试使用已预热的缓存，不代表首次打开文件或首次合成整张画布的耗时。
- 没有据此声称启动、文件读写、内存占用或所有实际绘画操作都变快。
